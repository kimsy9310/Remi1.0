# Remi 1.0

식품 레시피 포뮬레이터. 레시피의 맛·식감·물성을 원하는 방향으로 바꾸려면
**무엇을 얼마나 넣을지**를 최소 실험으로 찾아준다.

이 저장소는 **웜루프**를 담는다 — 실측 데이터로 사전지식을 보정하고 다음 실험을
제안하는 되먹임 고리. 프로젝트의 심장이고, 2026-08-25 이전까지 한 번도 실측으로
돌아본 적이 없던 부분이다.

```
온톨로지 사전값  ──┐
                  ├─→  보정된 모형  ──→  다음 배합 제안  ──→  (랩에서 제조·평가)
실측 (배합, 관능) ─┘                                              │
        ▲                                                         │
        └─────────────────────────────────────────────────────────┘
```

---

## 빠른 시작

```bash
pip install -r requirements.txt
streamlit run app/main.py
```

윈도우에서는 `run.bat` 을 더블클릭해도 된다.

앱이 열리면 `data/beverage_warmloop_260720.xlsx`(쌀 우유 시제품 18건)가 이미
들어 있어 바로 네 탭을 볼 수 있다.

| 탭 | 하는 일 |
|---|---|
| ① 데이터 | 실측 xlsx 를 읽어 무엇이 들어왔는지, 무엇이 빠졌는지 |
| ② 학습 | 사전값을 실측이 얼마나 밀어냈는지 · 부호가 뒤집힌 칸 |
| ③ 제안 | 목표 관능을 정하면 다음 배합을 제안 |
| ④ 팔레트 | 재료·등급·작업 범위 — **제안의 신뢰도를 결정하는 곳** |

## 구조

```
app/            Streamlit 앱
  main.py         UI (4탭)
  dataio.py       실측 xlsx → (X, Y).  단위 정규화와 컬럼 매핑을 흡수
  warmloop.py     사전 + 실측 → 보정된 모형 → 제안
  palette.py      palette.xlsx → 재료 목록·등급·작업 범위
  store.py        SQLite. 실행 이력
tools/
  build_palette.py   shortlist xlsx → 기계가독 palette.xlsx (1회성 변환)
engine/         최적화 엔진
  formulator/     mixture.py(혼합물 모형) · v2adapter.py(온톨로지 → 모형) 등
  selfcheck_model.py   v1 수학 회귀 18건
  selfcheck_v2.py      v2 경로 회귀 36건
ontology_v2/    온톨로지 (L·A·M·C·S·R 6층)
  layers/         YAML 31개
  tests/          loader_reference.py — 스펙이 지정한 정본 로더
data/           실측 xlsx · remi.db(로컬, git 제외)
```

### 세 층의 역할

- **온톨로지** — 재료·물성·관능 지식을 컴퓨터가 읽는 형태로 정리한 그래프.
  무엇이 무엇을 움직이는지(Γ₀)와 그 믿음의 세기(Λ)를 준다.
- **엔진** — 혼합물 제약(Σx = 100) 위에서 도는 구조화 베이지안.
  `Γ̂ = (ZᵀZ + Λ)⁻¹(ZᵀY + ΛΓ₀)` — Λ 가 크면 사전, 작으면 데이터.
- **앱** — 위 둘을 사람이 쓸 수 있게 감싼 것.

## 데이터 형식

`data/*.xlsx` 에 네 시트를 둔다. 컬럼 이름이 곧 규약이다.

| 시트 | 내용 |
|---|---|
| `recipes` | `sample_id` · `is_benchmark` · `ing_*` (배합) |
| `sensory` | `sample_id` · `rep` · `sens_*` (벤치마크 상대, −3…+3) |
| `dictionary` | `ing_*` 컬럼 → `ING.*` 온톨로지 ID |
| `instrumental` | (선택) 물성 실측 |

두 가지를 앱이 알아서 흡수한다.

- **단위** — 배합은 배치 그램으로 적어도 된다. 행마다 100 으로 정규화한다.
- **컬럼 이름** — `sens_*` 를 `L.*` 축에 잇는 다리는 M 카드의 `legacy_column`
  필드다. 매핑이 코드가 아니라 온톨로지에 있으므로, 새 제품은 카드만 쓰면 된다.

빈 템플릿은 `dataio.write_template()` 으로 만든다.

### 평가 규약

- 벤치마크 대비 **상대평가**. 0 = 벤치마크와 같음, ±3 이 끝.
- 벤치마크 자신은 전 축 0 으로 적고 `is_benchmark=yes` 로 표시.
- 같은 샘플을 여러 번 평가했으면 `rep` 을 늘려 적는다. 평균을 쓴다.
- 축별 정의와 주의사항은 M 카드의 `evaluation_note` 에 있고, 템플릿 README
  시트에 자동으로 실린다.

## 팔레트 표 (`data/palette.xlsx`)

재료 범위의 **정본**이다. DB 가 아니라 엑셀인 이유는 이 프로젝트의 모든 큐레이션이
이미 엑셀로 되어 있고, 등급·근거·메모를 함께 보면서 고치는 일이라서다.

한 줄이 (프로파일 × 재료) 하나다.

| 열 | 채우는 주체 | 뜻 |
|---|---|---|
| 프로파일 · 슬롯 · 재료 · 온톨로지ID | 사람 | 슬롯 = 기능군. **슬롯 하나가 모형의 변수 하나** |
| 등급 | 사람 | 필수 / 권장 / 옵션 / 제한 / 제외 |
| 하한 · 상한 | **사람** | 제안의 상·하한이자 사전계수의 스케일 |
| 범위근거 | 사람 | 그 숫자가 어디서 왔는지 |
| 담당축 | **자동** | 온톨로지가 계산한, 이 재료가 움직이는 목표축과 방향 |
| 확인 | 자동 | 온톨로지에 없는 ID 등 |

`icecream_palette_shortlist.xlsx`(기능군 8개 × 등급 5단계, 사람이 만든 큐레이션)를
`tools/build_palette.py` 로 변환해 만들었다. 변환이 푼 것:

- 한 줄에 묶여 있던 ID 를 쪼갠다 (`ING.a / b / ...c` 같은 혼합 표기 포함)
- 기능군 헤더를 각 행에 슬롯으로 내려 붙인다
- **풀어낸 ID 를 전부 온톨로지에 대조**하고, 못 찾은 것은 '확인' 열에 남긴다
  (조용히 비슷한 걸 갖다 붙이지 않는다)
- 담당축을 온톨로지에서 계산해 채운다

쌀 우유 행은 실측 데이터의 실제 사용 폭에서 씨앗을 넣었다. 전부 "검토 필요" 로
표시돼 있다 — 실제로 쓴 범위이지 쓸 수 있는 범위가 아니다.

> 생성기를 다시 돌리면 이 파일을 덮어쓴다. 손으로 채운 값이 있으면 먼저 복사할 것.

앱 ④ 탭에서 바로 편집·저장할 수 있고, 저장하면 이 파일에 되쓴다.

### 이 표가 바로 잡아주는 것

- **목표축 커버리지(G2)** — 축마다 그 축을 움직이는 재료가 몇 개인지. 0 이면 그
  축은 목표로 줘도 반응하지 않는다.
- **못 쓰는 재료** — 담당축이 빈 재료. 배합에는 넣을 수 있지만 조종 수단은 아니다.
  아이스크림에서 바닐라·소금이 여기 걸린다 (소금은 온톨로지에 `function_tags` 가
  아예 없다 — 결손이다).
- **퇴화한 범위** — 상한 ≤ 하한. 실측에서 한 수준만 쓴 재료가 여기 걸린다.

## 지금 무엇이 되고 무엇이 안 되나

### 되는 것

쌀 우유 실측 18건으로 웜루프가 돈다. 실행 결과:

- 자유변수 15개 중 데이터가 실제로 탐색한 **독립 방향은 11개**
  (샘플 수가 아니라 이 값이 배울 수 있는 양을 정한다)
- 사전이 비어 있던 칸 **44개**를 데이터가 채웠다
- 사전과 **부호가 뒤집힌 칸 2개** — 둘 다 Λ 가 낮고 이동이 작아 약한 증거다

목표를 주면 그에 맞는 배합이 나온다. 예: body +1.0 · 산화취 −1.0 →
잔탄검 ↑, 아라비아검 ↓, 현미호분 유화제 ↑ (예측 body +1.00 · 산화취 −0.99).

### 안 되는 것 / 주의

- **재료 범위(④ 탭)가 비어 있으면 제안 숫자를 믿을 수 없다.** 온톨로지의
  `limitations` 가 자유 서술이라 기계가 못 읽는다. 범위는 상·하한이자 사전계수의
  스케일이라, 없으면 임시 추정치를 쓰고 경고를 띄운다.
- **creaminess 축은 이번 데이터로 학습되지 않는다.** 20건 중 1건만 채워져 있다
  (원본 시트 메모: "creaminess=신규(과거 데이터 없음)"). 축이 사라진 게 아니라
  다음 배치에서 채우면 살아난다.
- **팔레트는 사람이 정한다.** 목표축을 덮는지 자동 검사는 하지만, 자동 선택은
  하지 않는다. 온톨로지가 유화제 10종을 구분하지 못하기 때문이다(아래 참조).
- 순서형 반응(JAR·±3)을 연속으로 다룬다. 척도 끝에 몰린 데이터에서 편향이 생긴다.

## 새 제품 추가하기

쌀 우유(`layerM_cards_beverage_rice_milk.yaml`)가 최근 사례이고, 커피밀크가
그 이전 사례다. 순서는 이렇다.

1. **M 카드를 쓴다** — 제품이 실제로 평가받는 축을, 그 제품의 언어로.
   `legacy_column` 에 엑셀 컬럼 이름을 적으면 데이터가 자동으로 붙는다.
2. **`EXTRA_PROFILES` 에 등록**한다 (`engine/formulator/v2adapter.py`).
3. **`loader_reference.py` 로 검증**한다. 불변식 6(도달성)이 걸리면 그 축을
   움직이는 재료가 없다는 뜻이다 — C 엣지나 R-1 레코드를 보태야 한다.
4. **④ 탭에서 재료 범위**를 넣는다.

쌀 우유를 붙일 때 3번에서 `creaminess`·`oiliness` 가 걸렸고,
`FT.fat_source → P.oil_phase_fraction` 이 소스 스코프에만 있던 것이 원인이었다.
`layerC2_ext_beverage_fat_scope.yaml` 과 R-1 레코드 `PO.0059`/`PO.0060` 으로
고쳤다. 두 파일 모두 DRAFT 로 표시돼 있으니 도메인 검토가 필요하다.
