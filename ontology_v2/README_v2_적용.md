### 1.2 Layer A 결손이 해소됐다

v2 스펙과 README 는 `layerA_parameters.yaml` 이 "인계되지 않았다"고 적고 있었다.
그 파일은 v1 작업본(`recovered_food_recipe_app/layerA_parameters.yaml`)에 있었고,
스펙이 말한 **37개 파라미터와 정확히 일치**함을 확인해 정본으로 편입했다.

편입하며 두 가지를 손봤다. 둘 다 파일 안에 표시돼 있다
(`grep -n "unit_status\|added_in" layers/layerA_parameters.yaml`).

| 항목 | 조치 | 확인 필요 |
|---|---|---|
| `unit` 누락 6건 | 각 항목의 `measurement.method` 에서 유도해 채움 | **랩 관례와 대조 필요.** DSC→degC, penetrometer→N, meltdown→g/min, 등 |
| `P.shear_thinning_index` | 신규 추가 | 정의 선택에 판단이 들어감 — 아래 참조 |

`P.shear_thinning_index` 는 R-1 레코드 `PO.0009` 가 참조하는데 정의가 없어
매달려 있던 항목이다. **점도비**(저전단/고전단)로 정의했다. 멱법칙 지수 `n` 으로
정의하면 전단담화가 심할수록 값이 낮아지는데, `PO.0009` 는
`monotone: increasing` 이라 모순이 생긴다. 점도비는 전단담화와 함께 커지므로
기존 레코드가 쓰인 그대로 맞다. 랩에서 `n` 으로 보고하고 싶다면 이 항목을
재해석하지 말고 별도 파라미터를 추가하고 `PO.0009` 의 짝을 만들 것.

**결과: 파라미터 38종, `unit` 누락 0건, 매달린 `P.*` 참조 0건.**

### 1.3 mixture.py 세 곳을 고쳤다

수정 전 파일은 `engine/formulator/mixture.py.bak_20260824_165135` 에 있다.

**B1 — 사전계수 스케일.** `fit_prior_only` 가 `zsd` 를 조용히 `1` 로 두고 있었다.
사전은 "1 표준편차당 효과" 인데 모형은 "1 퍼센트포인트당" 으로 읽었다.

```
고치기 전:  알룰로스 20 pp  ->  단맛 +20.0     (관능 척도는 ±3 에서 포화)
```

이것 때문에 옵티마이저가 "이미 너무 달다" 고 판단해 감미료를 전부 빼버렸다.
이제 `zsd` 는 필수 인자다. 사전이 이미 원단위라면 `zsd="unit"` 으로 **명시적으로**
선택해야 한다. 기본값을 없앤 이유는, 멈추지 않고 틀리는 오류였기 때문이다.

**B3 — Γ₀ 행 수.** 조립기는 팔레트 전체에 대해 Γ₀ 를 만들지만 모형은 필러를 뺀
자유변수를 쓴다. 검증이 없어서 한참 뒤 `propose()` 안에서 broadcast 오류로
터졌다. 이제 적합 시점에 거부하고, 메시지가 필러 행을 빼라고 알려준다.

**B4 — 엣지별 확신도.** Λ 를 `(q,)` 로만 받아서 호출부가 재료별 최솟값으로
축약해야 했다. 실측해보니 `{0.4, 2.0, 8.0}` 세 값이 **한 값으로** 뭉개졌다 —
구조화 베이지안의 핵심이 사라진다. 이제 `(q, m)` 을 받고 반응 열마다 능선
방정식을 따로 푼다(열끼리 독립이라 근사가 아니다). `(q,)` 도 계속 받는다.

`fit()`, `predict()`, 유효 자유도 계산이 함께 바뀌었다. `Ainv` 는 이제
`(m, q, q)` 다.

### 1.4 어댑터가 생겼다

`engine/formulator/v2adapter.py`. v1 로더는 **고치지 않고 그대로 뒀다** — v1
온톨로지로는 여전히 정상 동작한다(확인함: structure_classes 3 · params 29 ·
sensory 55). v1 로더에 v2 를 넣으면 예외 없이 빈 객체가 나오므로, 섞어 쓰지 말 것.

어댑터는 스펙이 정본으로 지정한 `tests/loader_reference.py` 를 불러다 쓴다.
그 파일의 네 규칙(alias 접기 · 스코프 정규화 · R-1 합성 · 활성 term 도달성)은
각각 스모크테스트 실패에서 나온 것이라 **다시 구현하면 안 된다.**

```python
from formulator.v2adapter import V2Ontology

onto  = V2Ontology()
built = onto.build("icecream", palette, bounds=상한표)
print(built.report())                      # 왜 이런 모형이 됐는지
x     = onto.suggest(built, {"L.tx.creaminess": +1.0}, bounds=상한표)
```

## 3. 아직 남은 것

### 3.1 대표님 판단이 필요한 것

**재료별 용량 상한표 (최우선).** 온톨로지의 `limitations` 35건이 자유 서술이라
기계가 못 읽는다(스펙의 G5). 상한이 없으면 `propose()` 가 물리적으로 불가능한
용량을 낸다. 어댑터는 범위 없이 부르면 경고를 남기고 임시 스케일을 쓰지만,
그 스케일은 **추정치이므로 숫자를 믿을 수 없다.**

형식은 `v2adapter.DEMO_ICECREAM` 을 그대로 따르면 된다:

```python
{"ING.allulose": (9.0, 15.0), "ING.guar_gum": (0.15, 0.35), ...}
```

이 표가 생기면 스케일(zsd)과 제안 경계가 동시에 해결된다. 지금 파이프라인에서
가장 값이 큰 한 가지다.

**Layer A 단위 6건 확인.** 위 1.2 표 참조. 랩 관례와 다르면 고쳐야 한다.

**정본 온톨로지 확정.** v1 YAML(엔진용) · v1 JSON(앱용) · v2 YAML 세 세대가
아직 공존한다. 이번 작업은 v2 를 쓸 수 있게 만들었을 뿐, 나머지를 정리하지는
않았다.

### 3.2 아직 안 한 것

- **앱 재배선.** Streamlit 프로토타입(`_웹프로토타입/`)은 여전히 v1 JSON 스냅샷
  (`ontology_export.json`, SA.\* 261건)을 읽고, 최적화 엔진과 연결돼 있지 않다.
- **팔레트 큐레이션 (G2).** 축마다 조종 수단을 보장하는 규칙이 없다. 어댑터는
  움직일 수 없는 축이 있으면 경고만 한다. 데모에서 순진한 자동 선택이
  아이스크림에 고추장을 고른 적이 있다 — 팔레트는 사람이 정해야 한다.
- **방향 없는 엣지 18건 (G3).** 효과 엣지 107건 중 17%가 `direction` 이 없어
  조용히 0 기여한다.
- **구조적으로 빈약한 축.** `L.ar.milky` 는 전체 팔레트를 다 써도 액추에이터가
  1개, `L.ar.coffee` 는 2개다. 커피밀크 프로파일에서 이 축들은 사실상 조종되지
  않는다.
- **순서형 반응.** JAR 1-5 와 ±3 을 연속으로 다룬다. 척도 끝에 몰린 데이터에서
  편향이 생긴다(스펙 §5.6 이 요구하는 순서형 링크는 미구현).
