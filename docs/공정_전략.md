# 공정을 어떻게 다룰 것인가

2026-09-02. **아직 구현하지 않았다.** 착수 전에 이 문서를 다시 읽을 것.

문제 제기: 같은 배합이라도 공정 하나가 바뀌면 결과가 크게 달라지는데, 우리는
지금까지 공정을 통째로 빼놓고 만들어 왔다. 공장 공정을 시뮬레이션할 여력이
없다는 이유였지만, 소규모 주방 공정조차 고려하지 않고 있었다.

---

## 1. 진단 — 지금 무슨 일이 일어나고 있나

### 1.1 모형이 공정 탓을 재료에 돌리고 있다

엔진은 관능을 배합의 선형 함수로 본다.

    y = Γᵀ z        z = 필러 기준 배합, Γ = (자유변수 q × 축 m)

이 식에 공정이 없다. 그러면 두 시료가 **다른 공정으로** 만들어졌고 하나가 더
크리미할 때, 적합은 그 차이를 **재료 계수에 얹는다.** 조용히 틀린다 — 경고도
잔차 이상도 뜨지 않는다. 그냥 Γ 가 조금씩 어긋난 채로 그럴듯한 답을 낸다.

### 1.2 실측 데이터에 공정 칸이 하나도 없다

`data/beverage_warmloop_260720.xlsx` 의 `recipes` 시트 23열을 전부 열어 봤다.

    sample_id · project · is_benchmark · structure_class · date · notes
    ing_* (재료 16개) · total_check

`instrumental` 시트도 점도·Brix·pH·탁도·밀도뿐이다. **균질 압력도, 가열 온도도,
교반 조건도, 장비도 없다.** `date` 는 20건 전부 비어 있고 `notes` 도 0건이다.

즉 **파일만 봐서는 20건이 같은 공정이었는지 알 수 없다.** 이번에는 사용자에게
물어 "모두 같은 공정" 이라는 답을 받았으므로 Γ 는 깨끗하다(5.4 절). 그러나
그 답은 파일이 아니라 대화에 있다 — 다음 배치가 다른 공정으로 들어와도
합쳐지는 것을 막을 장치가 데이터 안에 없다.

### 1.3 제형마다 공정 노출도가 다르다 — 아이스크림은 80%

Layer A 의 38개 파라미터를 재료가 움직일 수 있는지로 갈라 보고, R-1 을 타고
각 제형의 core 축에 닿는지 계산했다.

| 제형 | core 축 | 공정에 걸린 축 | 비율 |
|---|---|---|---|
| **아이스크림** | 5 | **4** | **80%** |
| O/W 음료 | 4 | 2 | 50% |
| O/W 소스 | 7 | 3 | 43% |
| 현탁액 | 6 | 2 | 33% |
| 커피우유 | 7 | 2 | 29% |
| 발효 핫소스 | 10 | 2 | 20% |
| 쌀음료 | 5 | 1 | 20% |

아이스크림은 core 5축 중 4축이 공정에 걸린다 — 얼음 결정 크기, 지방 부분합일,
오버런, 믹스 점도. 당연하다. **아이스크림은 동결이 제품 그 자체다.**

### 1.4 재료로는 아예 못 움직이는 축이 있다

파라미터 38개 중 **재료가 못 움직이는데 관능에는 이어진 것이 3개**다.

| 파라미터 | 관능 축 | 실제 액추에이터 |
|---|---|---|
| `P.particle_size_d90` | 꺼끌거림 (현탁액 core) | **분쇄 입도** |
| `P.serving_temperature` | 차가움 | **제공 온도** |
| `P.flavor_release_dynamics` | 뒷맛 길이 | 매트릭스·공정 |

사용자가 "덜 꺼끌거리게" 라고 하면 정직한 답은 **"더 곱게 가세요"** 인데,
지금 `C4 GAPFILL` 은 "그 축을 움직일 재료가 없습니다" 라고 말한다. 틀린 말은
아니지만 쓸모없는 말이다.

## 3. 문헌이 말하는 것

### 3.1 이건 정립된 문제다 — Cornell 의 crossed mixture-process design

배합 실험의 반응이 배합 비율뿐 아니라 **만드는 과정의 설정값에도 달려 있다**는
것은 1982년 Cornell 이 정식화했다. 어묵 패티 실험 — 생선 3종의 배합 × 공정변수
3개(오븐 온도, 오븐 시간, 튀김 시간)를 교차시켰다.

수학적으로는 이렇게 된다. 배합 계수가 **공정 설정의 함수**가 된다.

    y = Σ βᵢ(z) · xᵢ        z = 공정 설정

우리 Γ 는 `β(z)` 를 특정 `z` 하나에서 잰 값이다. `z` 가 바뀌면 Γ 가 바뀐다.
지금 우리는 `z` 를 기록하지 않으므로 **어느 `z` 의 Γ 인지 모른다.**

### 3.2 균질 하나만 봐도 교차 구조가 그대로 보인다

고압 균질에서 액적 크기는 **압력, 패스 수, 그리고 유화제/기름 비율**이 함께
정한다. 앞의 둘은 공정이고 마지막은 배합이다. 같은 파라미터
(`P.droplet_size_d32`)를 양쪽이 함께 움직인다 — 교차 구조의 교과서적 예다.
압력 의존은 대체로 멱법칙(`d ∝ P^-a`)을 따른다.

### 3.3 전량 교차 설계는 우리 전제와 충돌한다

crossed design 은 실험 수가 **곱해진다**. 배합 7점 × 공정 4조건 = 28회.
우리 전제는 "DoE 는 적을수록 좋다, 첫 배합은 하나여도 좋다" 다. 정면 충돌이다.
그래서 **전량 교차는 지금 할 일이 아니다.**

### 3.4 대신 쓸 수 있는 것 — 최소 정보 표준

생물학 쪽이 재현성 위기를 겪고 내놓은 답이 MIAME/MIBBI 류의 **최소 정보 표준**
이다. 실험을 재현하는 데 반드시 필요한 항목만 정해 놓고 그것만 기록하게 한다.
모델링하지 않고 **기록**만으로 오염을 막는다. 우리에게 맞는 것이 이쪽이다.

## 4. 전략 — 세 가지 일로 나눈다

공정을 다루는 일은 하나가 아니다. 비용과 가치가 완전히 다른 셋이 섞여 있었다.

| | 하는 일 | 비용 | 없으면 |
|---|---|---|---|
| **1** | **거짓말하지 않기** — 공정을 기록하고, 다른 공정 데이터를 섞지 않는다 | 거의 없음 | 조용히 틀린다 |
| **2** | **레버를 놓치지 않기** — 공정도 조종 수단으로 제안한다 | 중간 | "재료가 없습니다" 로 끝난다 |
| **3** | **공정까지 최적화** — 배합 × 공정 동시 탐색 | 실험 수가 곱해짐 | 배합만 최적 |

**1번이 시급한 전부다.** 1번은 도구를 똑똑하게 만들지 않는다 — **자신 있게
틀리는 것을 멈추게 한다.** 지금 상태가 정확히 "자신 있게 틀리는" 상태다.

---

## 5. 1단계 — 공정 기록 (최소 정보 표준)

### 5.1 원칙 두 개

**(a) 답을 바꾸는 것만 묻는다.** 제형마다 core 축이 어떤 파라미터에 걸려 있는지는
1.3 절처럼 **계산된다.** 공정 질문도 관능 질문처럼 **온톨로지에서 생성**한다.
하드코딩하지 않는다.

**(b) 1번 일에는 값이 아니라 동일성만 있으면 된다.** "같은 공정이었나?" 만
답하면 오염을 막을 수 있다. 값은 2·3단계에서 필요하다.

### 5.2 공정 카드

프로젝트마다 한 장. 필드는 제형이 정한다.

```yaml
process_card:
  profile: icecream
  scale: kitchen | pilot | plant
  steps:
    - op: OP.freeze_batch
      equipment: "가정용 아이스크림 메이커 ○○"
      knobs: { time_min: 25, target_overrun_pct: 30 }
    - op: OP.age_mix
      knobs: { hours: 12, temp_C: 4 }
  fingerprint: sha1(...)      # 같으면 같은 공정
  declared_at: 2026-09-02
```

`fingerprint` 가 핵심이다. 시료마다 이 값을 달아 두면:

- 같은 지문 → 한 덩어리로 적합해도 된다
- 다른 지문 → **다른 블록.** 블록마다 시료가 2건 이상이면 블록 절편을 따로
  두고(값싼 3단계), 1건뿐이면 분리할 수 없으므로 **경고하고 사용자가 정한다**

### 5.3 제형별로 무엇을 묻나 (계산 결과)

| 제형 | 걸린 파라미터 | 물을 것 |
|---|---|---|
| 아이스크림 | 얼음 결정, 지방 부분합일, 오버런, 믹스 점도 | 동결 장비 · 동결 시간 · 오버런 · 숙성 |
| O/W 소스 | 액적 크기, 겉보기 점도, 항복응력 | 유화 장비 · (고압이면) 압력·패스 · 가열 |
| O/W 음료 | 겉보기 점도, 탁도 | 균질 여부·압력 · 살균 조건 |
| 현탁액 | **입도 d90**, 겉보기 점도 | 분쇄 장비·입도 · 가열 |
| 쌀음료 | 겉보기 점도 | 균질 여부 |

**3~5개면 끝난다.** 사용자가 자기 공정을 아는 제품개발자라는 전제는 유효하다 —
다만 그것을 **적어 두게** 해야 한다.

### 5.4 지금 데이터에 대한 조치 — **답을 받았다 (2026-09-02)**

> **"모두 같은 공정이야."** — 사용자

**따라서 쌀음료 20건은 블록 하나이고, 지금 Γ 는 오염되지 않았다.** 다시 적합할
필요 없고 불확실성을 키울 이유도 없다. 이 데이터에 관한 한 1 절의 우려는
해당되지 않는다.

다만 **그 사실이 파일 어디에도 없다.** 확인해 보니:

| 칸 | 상태 |
|---|---|
| 공정 관련 열 | **없음** (23열 전부 재료·메타) |
| `date` | **20건 전부 비어 있음** — 시간 순서조차 알 수 없다 |
| `notes` | **0건** |
| `rep` | 전부 1 — **반복이 한 번도 없어 σ 를 잰 적이 없다** |

즉 "같은 공정" 이라는 사실은 **이 대화에만 존재한다.** 적어 두지 않으면 다음
사람도, 다음 세션도 알 수 없고, 다음 배치가 다른 공정으로 들어와도 조용히
합쳐진다. 이것이 1.7 이 하는 일이다.

**1.7 의 첫 작업은 이 선언을 파일에 박는 것이다:**

    process_block: RM-P1
    declared_by: user, 2026-09-02
    scope: beverage_warmloop_260720.xlsx 전 20건
    detail: 미상 — 동일하다는 것만 확인됨

`detail` 이 비어 있어도 **지문이 같다는 사실만으로 1단계 목적은 달성된다**
(5.1 (b)). 값은 2단계에서 필요하고, 그때는 새 배치부터 받으면 된다.

## 6. 2단계 — Layer O, 기존 파라미터 위의 두 번째 액추에이터

### 6.1 모델을 다시 짤 필요가 없다

"공정 단위로 모델을 재설계해야 하나" 에 대한 답: **아니다.** 온톨로지의 파라미터
층이 이미 올바른 이음매다.

    재료 ──┐
           ├──> P.*  ──R-1──> L.*  (관능)
    공정 ──┘

`R-1` 이 이미 `P → L` 을 나른다. 공정은 **같은 P 를 움직이는 두 번째 부류의
액추에이터**로 들어오면 되고, 관능까지는 공짜로 도달한다. 새 관능 기계가
필요 없다.

### 6.2 Layer O 항목 모양

```yaml
- id: OP.homogenize_hp
  ko: 고압 균질
  sets:
    - to: P.droplet_size_d32
      direction: decrease
      form: power_law              # d ∝ P^-a  (문헌)
      knob: pressure_bar
      confidence: medium
  knobs:
    pressure_bar: { pilot: [100, 1000], plant: [100, 2000] }
    passes:       { pilot: [1, 3],      plant: [1, 3] }
  scale_bands: [pilot, plant]      # 주방에는 없다
  alternative_at_kitchen: OP.shear_rotor_stator
```

### 6.3 규모 밴드가 중요하다

주방에서 500 bar 는 불가능하다. 같은 목표가 파일럿에서는 닿고 주방에서는 안
닿는다. `scale` 을 받아 두면 `D0 FEASIBILITY` 가 이렇게 말할 수 있다:

> "이 크리미함은 지금 장비로는 닿지 않습니다. 고압 균질(150 bar 이상)이 필요한데
> 주방 규모에는 없습니다. 대안: 유화제를 늘리거나, 목표를 +1 로 낮추세요."

**이게 2단계가 사는 값이다.** 1단계는 틀리지 않게 하고, 2단계는 길을 알려 준다.

## 7. 3단계 — 공정까지 최적화 (미룬다)

전량 crossed design 은 실험 수를 곱한다. 우리 전제와 충돌하므로 미룬다.
다만 **값싼 절반**은 1단계에서 이미 얻는다 — 블록별 절편은 블록마다 2건이면
추정된다. 기울기까지 공정에 따라 다르게 두는 것(`β(z)`)이 진짜 3단계이고,
그건 공정을 **일부러 흔든** 실험이 있어야 한다.

들어갈 시점의 신호: 같은 배합을 다른 공정으로 만들었을 때 잔차가 σ 를
크게 넘는 일이 반복될 때.

## 8. 알고리즘 어디에 들어가나

### 8.1 새 단계 `C0 PROCESS`

Phase C 의 머리에 붙인다. Phase C 의 질문이 "무엇을 쓰나" 에서
**"무엇으로 어떻게 만드나"** 가 된다.

| 단계 | 이름 | 누가 | 하는 일 |
|---|---|---|---|
| **C0** | **`PROCESS`** | 사 | 규모와 공정을 선언한다. 필드는 제형이 정한다(3~5개) |
| C1 | `SEED` | R | A4 의 재료를 초기 집합으로 |
| … | | | |

**왜 C 인가.** 공정은 재료와 같은 부류다 — *가진 것*이고, *닿을 수 있는 범위를
제한*한다. B(목표)도 A(정체)도 아니다.

### 8.2 다른 단계에 미치는 영향

| 단계 | 무엇이 달라지나 |
|---|---|
| `C4 GAPFILL` | 빈 곳이 재료뿐 아니라 **공정**일 수 있다 — "더 곱게 가세요" |
| `D0 FEASIBILITY` | 규모로 못 가는 목표를 가려낸다. 대안을 함께 낸다 |
| `D3 EXPLAIN` | 제안이 배합이 아니라 **배합 + 공정**이 된다 |
| `E1 RECORD` | 실제로 쓴 공정을 받는다. 선언과 다르면 **경고하고 블록을 나눈다** |
| `E2 REFIT` | 블록이 다른 데이터를 섞지 않는다 |
| `D4 DOE` | 공정을 고정하는 것이 시료 수를 줄이는 가장 값싼 방법이다 |

마지막 줄이 중요하다. **공정을 고정하면 DoE 가 줄어든다** — "적을수록 좋다" 와
같은 방향이지 반대가 아니다.
