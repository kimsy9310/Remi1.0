# ±3 척도 정의 — 다른 채팅 인계용

아래 블록을 **새 채팅에 그대로 붙여넣으면** 된다. 이 채팅(사용자 화면 재설계)은
그동안 착수 순서 1번(`B1 SCOPE`)을 진행한다.

```
Remi 라는 식품 배합 포뮬레이터를 만들고 있어. 저장소는
C:\Users\user\OneDrive\Desktop\Remi 1.0\Remi1.0 이고, 온톨로지는 ontology_v2/,
엔진은 engine/formulator/, 앱은 app/ 에 있어.

이 채팅에서는 딱 한 가지만 판다: **관능 척도 ±3 이 정확히 무엇을 뜻하는가.**
모델 내부의 정의와, 사용자에게 보여줄 설명을 동시에 정해야 해.
앱 UX 나 질문 흐름은 다른 채팅에서 하고 있으니 건드리지 마.

## 지금 상태 (전부 확인된 사실이야)

1. 관능 점수는 **벤치마크 상대**야. 0 = 기준 제품과 구분되지 않음, ±3 이 양 끝.
   M 카드의 scale_type 이 diff_7 인 것들이 이 척도를 쓴다.

2. 그런데 카드 70장 중 상당수는 scale_type 이 **jar_5** (Just-About-Right) 이고
   jar_target 문자열("match benchmark", "none detectable" 등)을 갖고 있어.
   화면은 둘을 구분하지 않고 전부 "기준보다 더/덜" 로 묻는다. 이게 맞는지 모르겠어.

3. 앵커 문장은 최근에 한글로 채워 넣었는데(ko.anchors, 70장 전부),
   **방향과 어조만 있고 크기가 없어**. 예:
     -3 "기준보다 뚜렷하게 덜 달다"
      0 "기준과 구분되지 않는다"
     +3 "기준보다 뚜렷하게 더 달다"
   "뚜렷하게" 가 당도로 몇 %인지, 관능적으로 몇 JND 인지는 아무 데도 없어.

4. 엔진에 RANGE_TO_SD = 4.0 이라는 상수가 있어
   (engine/formulator/v2adapter.py). 재료의 작업 범위(하한~상한) 폭을 4 표준편차로
   본다는 가정인데 근거가 검증된 적 없어. 이 값이 Γ₀ 의 스케일을 정하므로
   ±3 척도와 재료 용량을 잇는 환산계수 노릇을 하고 있어.

5. M 카드의 reliability 가 σ 로 매핑돼:
     high 0.5 / medium 1.0 / low 1.8
   즉 신뢰도 낮은 축은 ±1.8 이내 차이를 잡음으로 본다는 뜻인데,
   이게 ±3 척도 위에서 무슨 의미인지 사용자에게 설명된 적 없어.

6. 앵커가 -3/0/+3 이 아니라 **강도 기준점 목록**인 카드가 4장 있어:
   [{intensity: 3, reference: "icy low-fat ice-milk"}, {intensity: 14, ...}]
   이건 Spectrum 방식 절대 강도라 차이 척도와 뜻이 아예 달라. 공존시킬지 결정 필요.

7. 실측 데이터는 쌀음료 18건이 유일해
   (data/beverage_warmloop_260720.xlsx). 패널은 훈련되지 않았고,
   기준 시료(B00_bench)는 전 축 0 으로 기록돼 있어.

## 내가 답을 원하는 것

A. **±3 의 크기를 무엇으로 정의할 것인가.**
   후보: JND 배수 / 패널 표준편차 배수 / 카테고리 내 시판품 분포의 분위수 /
   순수 순서형(크기 정의를 포기하고 순위만) — 각각의 장단과, 훈련되지 않은
   패널·소수 시료(n=18)라는 우리 조건에서 무엇이 현실적인지.

B. **jar_5 와 diff_7 을 하나로 합칠 것인가, 갈라 둘 것인가.**
   합친다면 JAR 카드의 jar_target 을 차이 척도로 어떻게 옮기나.
   갈라 둔다면 화면에서 두 종류를 어떻게 다르게 물어야 하나.

C. **RANGE_TO_SD = 4.0 이 타당한가.** 아니라면 무엇으로 바꾸고 근거는 무엇인가.
   이 값이 바뀌면 기존 제안이 어떻게 달라지는지도 알려줘.

D. **사용자에게 뭐라고 설명할 것인가.**
   식품 배합가지만 관능과학 훈련은 안 받은 사람이 읽고 바로 답할 수 있는 문장.
   지금 앵커 문장을 어떻게 고쳐야 하는지 구체적으로.

E. **reliability→σ 를 사용자에게 어떻게 드러낼 것인가.**
   "이 축은 작은 차이를 못 믿는다" 를 어떻게 말할지.

## 진행 방식

- 먼저 저장소를 읽고 위 사실들을 직접 확인해줘. 내가 틀렸을 수도 있어.
- 결론 내기 전에 선택지와 트레이드오프를 정리해서 나랑 상의해.
- 최종 산출물은 docs/ 아래 문서 하나. 그걸 다른 채팅으로 가져갈 거야.
- 관능과학 문헌 근거가 필요하면 웹 검색해도 좋아.
- **코드나 온톨로지는 아직 고치지 마.** 결론이 나면 그때 별도로 진행한다.
```

## 왜 이 주제를 뗐나

모델 내부 정의(`RANGE_TO_SD`, reliability→σ)와 관능과학 문헌을 동시에 파야 하고,
결론이 온톨로지 카드(`ko.anchors`)와 엔진 양쪽에 닿는다. 사용자 화면 작업과 섞으면
둘 다 느려진다. 산출물이 문서 하나라 옮겨 오기도 쉽다.

결론이 나오면 이 저장소의 `docs/` 에 들어오고, 아래가 바뀔 수 있다:

- `ontology_v2/layers/layerM_cards_*.yaml` 의 `ko.anchors` 70장
- `engine/formulator/v2adapter.py` 의 `RANGE_TO_SD`
- 사용자 화면 `B3 GOALSET` 의 슬라이더 설명
- `B2 BENCHMARK` 를 비웠을 때의 처리
