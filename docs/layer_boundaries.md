# Layer boundaries — 어느 구간이 무엇을 참조하는가

2026-09-10. 사용자 피드백 세 갈래를 처리하기 위한 **진단 문서**다. 고치지 않는다.

    Layer S 의 경계를 다시 긋자 — 제형과 제품이 섞이면 안 된다
    Layer A 와 R 의 역할이 불분명하다
    구간별로 무엇을 참조하는지 다시 보자

기준 알고리즘은 `Algorithm_Remi/1st_Draft_algorithm_remi.drawio`(2026-09-04)다.
`docs/상호작용_알고리즘.md` 의 단계 번호는 그 사이 바뀌었다 — **`B3` 이 없어지고
`B2 Target` 이 그 일을 하며, `D0 FEASIBILITY` 는 `C5 Feasibility` 로 내려왔다.**
이 문서는 최신 그림을 따른다.

## 2. 구간 × 레이어

**2026-09-10 정정.** 한 번은 "A2 가 읽기만 한다" 고 적었고, 다음엔 "초안을
쓴다" 고 고쳤는데 둘 다 틀렸다. 사용자 지적으로 정리된 실제 순서는 이렇다.

    ① API 가 문장을 **온톨로지와 무관하게** 분석한다 — flavor · texture · appearance
    ② 그 결과를 LEXICON 과 대조한다
    ③ 붙으면 그 말로 **치환**한다              <- 대부분. 읽기다
    ④ 안 붙으면 **새로 추가**한다              <- 예외. 쓰기다

곧 **A2 는 읽는 것이 본업이고, 쓰는 것은 어휘가 모자랄 때의 예외 경로**다.
쓰기가 얼마나 자주 일어나는지는 4.2 에서 쟀다.

| 구간 | 읽는다 | 쓴다 |
|---|---|---|
| `A2-1·2·3` | LEXICON (대조 대상) | 없는 말만 추가 (예외) |
| `A3` | 질문 은행 | |
| `A4` | LEXICON · STRUCTURE | **카드 초안** |
| `B1` | 카드에 적힌 LEXICON·STRUCTURE | **카드 수정 또는 별도 카드** |
| `B2` | B1 의 카드 | LEXICON 의 말로 **치환** → 목표 |
| `C0` | RELATION (액추에이터 없는 것) | 나중에 PROCESS |
| `C1·C2` | INGREDIENT | 미등록 재료 잠정 등록 |
| `C3·C4` | INGREDIENT + **RELATION** | |
| `C5` | STRUCTURE 범위 · PARAMETER 단위 | |
| `D1` | INGREDIENT·RELATION → Γ₀·Λ, 카드 → Σ₀ | |
| `E1` | 실측 | INGREDIENT 갱신분 (환류) |

**RELATION 이 B 에서 C 로 내려왔다.** 3.2 에서 다룬다.

## 3. 설명 요청 다섯

### 3.1 `B2` — M 앵커와 L 한글이 무엇인가

**LEXICON 의 `ko`** 는 축 이름 한 낱말이다. `L.tx.body` → `바디감`.
화면에서 축을 부를 때 쓴다.

**MEASUREMENT 앵커**는 그 축을 **±3 눈금 위에서 어떻게 읽을지**를 적은 문장
셋이다. 쌀음료의 바디감 카드를 그대로 옮기면:

```yaml
ko:
  anchors:
    '-3': 기준보다 뚜렷하게 묽고 물 같다
    '0':  기준과 구분되지 않는다
    '+3': 기준보다 뚜렷하게 묵직하고 꽉 찬다
  evaluation_note: 입에 넣었을 때의 묵직함과 꽉 찬 느낌을 봅니다.
                   크리미함과 헷갈리기 쉬우니 바디감을 먼저 판단하세요.
```

**핵심은 앵커가 제형마다 다르다는 것**이다. 같은 `L.tx.body` 라도 음료에서는
"묽고 물 같다" 지만 소스에서는 다른 문장이어야 한다. LEXICON 은 맥락 없는 정의
하나만 갖고, 맥락은 전부 MEASUREMENT 가 진다. 그래서 `B2` 가 목표를 받을 때
읽어 주는 문장이 이것이다 — 사용자는 "바디감 +2" 가 아니라 **"기준보다 묵직한
쪽으로 2"** 를 고른다.

카드에는 `evaluation_note`(어떻게 판단하나)와 `jar_target`(무엇이 합격인가)도
있다. 셋이 한 축의 질문 한 장을 이룬다.

### 3.2 `B2` 에서 RELATION 을 보자던 제 주장은 틀렸다

사용자: *"재료 없이 감각-감각 관계를 고려하는 것은 의미가 없어 보여. 오히려
재료 리스트가 나오고, 그 이후에 배합을 짤 때 중요한 거지."*

**맞다. 그리고 반증이 온톨로지 안에 이미 있었다.**

제가 든 예는 `걸쭉함 +2 · 흐름성 +2` 였다. `IN.0003` 이 둘을 역상관이라
적었으니 못 이룰 목표라고 했다. 그런데 `P.shear_thinning_index` 의 R-1 노트가
이렇게 적혀 있다 —

> User-identified second driver (2026-08-18): **shear-thinning products pour
> despite high rest viscosity.**

사용자께서 직접 적어 넣은 기록이다. 전단박화 재료를 쓰면 정지 시 걸쭉하면서
따를 때 잘 흐른다. **`B2` 에서 막았다면 실재하는 제품을 잘못 막는 것이다.**
제 반례가 스스로를 무너뜨린다.

R-2 13건을 성격별로 갈라 보면 더 분명하다.

| 갈래 | 건수 | 언제 쓰이나 |
|---|---|---|
| 재료가 일으키는 맛 상호작용 (소금→쓴맛↓, 바닐라→단맛↑) | 5 | **재료가 있어야 뜻이 생긴다** |
| 같은 것을 두 번 세는 축쌍 (크리미-매끄러움-바디감 등) | 7 | 질문 설계 — 목표 타당성이 아니다 |
| 제공 조건 (차가움→단맛↓) | 1 | 평가 시점 주의 |

**목표를 받는 자리에서 쓸 것은 하나도 없다.** 앞의 5건은 명백히 `C`~`D` 고,
7건은 "같은 걸 두 번 묻지 마라" 라 **`B1`**(무엇을 물을지 정하는 곳)의 일이며,
1건은 카드의 `evaluation_note` 에 이미 적혀 있다.

그리고 사용자 말대로 **`C2·C3·C4` 에서 RELATION 이 들어가는 것이 맞다** —
재료와 카드를 대보려면 R-1(물성→감각) 없이는 대볼 수가 없다. 3.4 가 그 경로다.

### 3.2.1 곁가지로 나온 결함 — 특정 재료의 지식이 버려진다

위를 확인하다 실제 버그를 찾았다. 현탁액에서 잔탄의 흐름성 부호다.

    경로 A (태그, 직접)    FT.thickener      --decrease medium--> 흐름성
    경로 B (재료, 합성)    ING.xanthan_gum   --increase strong--> P.shear_thinning_index
                          P.shear_thinning_index --increasing--> 흐름성

    로더가 낸 결과: 부호 −, 크기 0.6, via=direct     <- 경로 B 가 버려졌다

`effects_of` 의 규칙이 `직접 엣지가 이긴다` 인데, 여기서 직접 엣지는
**태그**(일반)에서 왔고 합성 엣지는 **재료 override**(특정)에서 왔다.
2-tier 규칙은 재료가 태그를 덮는 것인데 **정확히 반대로 돌았다.**

그래서 모형은 잔탄을 "다른 증점제와 똑같이 흐름성을 떨어뜨리는 것" 으로 본다.
잔탄이 증점제 중에서 특별한 이유가 바로 그 반대인데도. 고칠 곳은 규칙 한 줄
이지만 정본 로더라 별도 판단이 필요하다.

### 3.3 `C2·C3` — 재료와 MEASUREMENT 카드를 대볼 수 있나

**가능하고, 이미 절반은 돌고 있다.** `V2Ontology.audit()` 의 G2 검사가 그것이다.

```
목표축(core 카드) 마다  →  그 축을 움직이는 재료가 팔레트에 몇 개인가
0 개면 경고 —  "목표에 넣어도 반응하지 않는다"
```

`C2·C3` 에 필요한 것은 방향을 뒤집은 같은 계산이다.

| 방향 | 질문 | 쓰이는 곳 |
|---|---|---|
| 축 → 재료 | 이 목표를 움직일 재료가 있나 | G2, `C3` |
| 재료 → 축 | 이 재료가 어느 목표에 닿나 | `C2` 검색 정렬 |
| 재료 → 축(음의) | 이 재료가 목표를 **거스르나** | `C5` 의 "counteracting" |

세 번째가 지금 없다. `C5` 그림이 *"Is there any counteracting ingredient?"* 를
묻는데, Γ₀ 의 부호를 보면 바로 나온다 — 같은 축에 대해 사용자의 목표 방향과
**반대 부호**를 가진 재료다. 계산은 한 줄이고, 아직 안 짰다.

**한 가지 걸리는 것.** 카드는 `core` 만 목표가 되는데(§5.7), `C2` 검색에서는
`monitored` 축도 보여야 유용하다. "이 재료는 꺼끌거림을 올립니다" 는 목표가
아니어도 알아야 할 정보다. 대조 대상을 core 로 할지 전체 카드로 할지가 정할 것.

### 3.4 `C4` — 도달 가능성이 실제로 계산되는 과정

`loader_reference.effects_of()` 가 재료 하나에 대해 도는 순서다.

**① 재료의 기능군에서 엣지를 모은다**

```
ING.xanthan_gum  →  FT.thickener  →  { P.apparent_viscosity ↑, P.yield_stress ↑ }
```

**② 재료 자신의 override 로 덮는다.** 2-tier 규칙이다. 기능군은 사전 뼈대이고,
재료가 벗어나는 곳만 자기 값을 쓴다.

**③ 스코프로 거른다.** 엣지마다 `scoped_to_structure_class` 가 있고, 프로파일의
스코프 집합에 있어야 산다. 점 경로(`SC.emulsion.ow.sauce`)와 정체성 문자열
(`SC.emulsion.ow|APP.sauce`)을 같은 것으로 보는 규칙이 여기 있다(§5.10).

**④ 감각(`L.*`)으로 바로 가는 엣지는 그대로 채택한다.**

**⑤ 물성(`P.*`)으로 가는 엣지는 RELATION R-1 과 합성한다.** 이것이 핵심이다.

```
EFFECT:    ING.xanthan  ──increase──>  P.apparent_viscosity
RELATION:  P.apparent_viscosity  ──increasing──>  L.tx.thickness
────────────────────────────────────────────────────────────
결과:      ING.xanthan  ──(+1 × +1)──>  L.tx.thickness   부호 +
```

부호는 두 방향의 곱이고, 크기는 EFFECT 쪽 magnitude 를, 신뢰도는 **둘 중 낮은
쪽**을 쓴다. R-1 도 스코프로 걸러진다 — 그래서 같은 재료가 소스에서는 닿고
음료에서는 안 닿는 일이 생긴다.

**⑥ 직접 엣지가 이긴다.** `via: direct` 가 있으면 합성 결과로 덮지 않는다.

에멀전 제형에서 식감·외관 축은 **대부분 ⑤ 로만** 닿는다(F6). 그래서 합성을
빼먹은 로더는 "층이 건강한데 모형이 안 도는" 상태를 만든다.

`C4` 가 할 일은 이 계산을 팔레트 전체에 돌려 **목표 축마다 닿는 재료 수**를
세고, 0 이면 무엇을 넣으면 되는지 되짚는 것이다. 되짚기는 같은 경로를 거꾸로
가면 나온다 — 축 → R-1 → 물성 → EFFECT → 그 물성을 움직이는 기능군.

### 3.5 `C5` — STRUCTURE 범위와 PARAMETER 단위가 하는 일

**STRUCTURE 의 범위**는 "이 제형에서 이 물성이 대개 얼마쯤인가" 다.

```yaml
- id: P.oil_phase_fraction
  plausible_range: '0.0001 - 0.15 (dilute; flavor/cloud emulsions often 10-100 ppm)'
- id: P.droplet_size_d32
  plausible_range: '0.1 - 1.0 (sub-micron needed for cloud stability; 0.2-0.5 typical)'
```

같은 `P.oil_phase_fraction` 이 소스에서는 `0.05 - 0.75` 다. **정의는 하나,
범위는 제형마다** — PARAMETER 와 STRUCTURE 를 가른 이유가 이것이다.

`C5` 에서 쓰이는 방식은 두 가지다. 하나는 목표가 이 범위 밖을 요구하면 튕기는
것이고(아직 안 짰다), 다른 하나는 **재료의 작업 범위를 세우는 것**이다 —
`slot_bounds()` 가 팔레트 표에 범위가 없는 재료를 만나면 STRUCTURE 의 정의
파라미터에서 받아 온다.

**여기 실제 약점이 둘 있다.**

**하나, 범위가 자유 서술 문자열이다.** 위 예시가 그대로 값이고, 코드가
정규식으로 숫자 둘을 긁는다. 괄호 안의 `10-100 ppm` 이 먼저 잡히지 않는 것은
운이다.

**둘, PARAMETER 의 `unit` 을 읽지 않고 값으로 단위를 추측한다.**

```python
if hi <= 1.0:               # 분율로 적힌 파라미터는 % 로
    lo, hi = lo * 100.0, hi * 100.0
```

`P.oil_phase_fraction` 의 `unit` 은 `'w/w fraction (0-1)'` 이고
`P.fat_content` 는 `'%'` 다. **PARAMETER 가 답을 갖고 있는데 코드가 안 보고
값의 크기로 짐작한다.** 지금은 맞아떨어지지만, 상한이 1.0 을 넘는 분율 표기가
하나만 들어와도 조용히 100 배 틀린다.

**그래서 "PARAMETER 단위의 의미" 에 대한 정직한 답은 — 지금은 문서일 뿐 아무도
안 읽는다.** 파라미터 값이 저장된 적이 한 번도 없기 때문이다(`remi.db` 의
`runs` 10행, CSV 어디에도 `P.*` 열이 없다). 단위가 일할 자리는 둘이다:
위의 분율/퍼센트 변환과, 훗날 실제 계측값을 받을 때.

### 3.6 `D1·D2` — Γ₀ 와 Λ 가 어떻게 만들어지나

`assemble()` 과 `build()` 가 하는 일을 순서대로 적는다.

**① 반응축을 고른다.** `core` 이고 `sample_aged` 가 아닌 카드만. 숙성 관찰은
시간 축이라 격리한다(§5.8). 그래서 쌀음료는 카드 16장 중 **5장**만 모형에 들어간다.

**② Γ₀ 를 채운다.** 재료 × 축 행렬이고, 각 칸은 3.4 의 도달 계산 결과다.

```
Γ₀[재료 j, 축 k] = 부호 × 크기          크기: weak 0.3 · medium 0.6 · strong 1.0
```

단위는 **"재료를 1 SD 움직였을 때 ±3 눈금에서 몇 칸"** 이다. 그래서 `0.6` 은
"작업 범위 1 SD 를 움직이면 관능 점수가 0.6 칸 움직인다" 를 뜻한다.

**③ Λ 를 채운다.** 같은 모양의 행렬이고, 각 칸은 **그 사전값을 얼마나 믿는가** 다.

```
Λ[j, k] = high 8.0 · medium 2.0 · low 0.4       엣지가 없으면 low
```

Λ 가 크면 실측이 사전값을 밀어내기 어렵고, 작으면 쉽게 밀린다. `E1` 에서
"데이터가 사전을 얼마나 밀어냈나" 를 재는 기준이 이것이다.

**④ Σ₀ 를 세운다.** 축 사이의 관측 잡음 공분산이다. 대각은 카드의
`reliability`(high 0.5 · medium 1.0 · low 1.8)의 제곱이고, **비대각은
RELATION R-2** 다 — 두 축이 상관이라고 적혀 있으면 그만큼 채운다.

**⑤ 스케일을 정한다.** 여기서 STRUCTURE 와 팔레트 범위가 들어온다.

```
zsd = (상한 − 하한) / 4.0        RANGE_TO_SD
```

작업 범위 전체를 4 SD 로 본다는 뜻이다. **이 4.0 이 `docs/척도정의_전략.md`
가 2.0 으로 바꾸자고 한 그 값이고, 승인 대기 중이다.**

**⑥ 필러 행을 뺀다.** 혼합물이라 합이 100 이고, 계수는 절대량이 아니라
**필러를 밀어내며 올릴 때의 변화**다(불변식 8). `γ_j = β_j − β_filler`.

`D2` 는 이 모형으로 목표에 가장 가까운 배합을 찾는다 — 합계 100, 재료마다
범위 안, SLSQP. scipy 가 없으면 경사하강으로 물러나는데 오차가 0.019 → 0.950
으로 벌어진다(트러플 마요 실측).

## 4. 무엇이 어떤 기준으로 켜지나 — 문제 정리

사용자 질문: *"M, L, A 가 어떤 기준으로 켜지는지 기준이 불분명하다"* 와
*"명사는 잡히는데 제형이 하나도 안 잡힌다"* 가 아직 문제인가.

**둘 다 문제이고, 서로 다른 문제다.**

### 4.1 켜지는 기준은 사실 셋인데 하나로 뭉쳐 불린다

| 질문 | 답하는 것 | 지금 상태 |
|---|---|---|
| 이 감각이 **존재하나** | EFFECT + RELATION 도달 가능성 | 계산된다. 기준 명확 |
| 여기서 **어떻게 재나** | MEASUREMENT 카드 | 손으로 쓴다. 없으면 못 묻는다 |
| **목표로 삼을 것인가** | 카드의 `tier` | **여기가 불분명한 자리** |

첫 줄은 규칙이 하나뿐이라 맑다 — 경로가 있으면 존재한다. 셋째 줄이 문제다.
`core` 를 정하는 규칙이 **어디에도 적혀 있지 않고**, 지금은 제품 M 카드 파일이
손으로 정한다. 제품 파일이 사라지면 그 근거가 통째로 없어진다.

그러니 **"기준이 불분명하다" 는 지적은 셋째 줄에 정확히 꽂힌다.** 앞의 둘은
기준이 있다.

### 4.2 제형이 안 잡히는 문제 — API 를 전제로 다시 쟀다

앞서 "명사는 잡히는데 제형이 하나도 안 잡힌다" 고 적은 것은 **API 없는
폴백**을 잰 것이었다. 사용자 지적대로 API 를 전제로 다시 쟀다.

**방법.** 예문 다섯에 대해 사람이 그 문장에서 읽어낼 서술어를 flavor ·
texture · appearance 로 적고(API 응답의 자리), 그것이 LEXICON 에 붙는지 본다.

**결과 ① 어휘는 거의 다 있다.**

    그대로 대조            18/28  (64%)
    괄호 접미사를 벗기면    26/28  (93%)

놓친 열 개 중 여덟이 **괄호 때문**이었다. LEXICON 의 `ko` 가 뜻을 가르려고
접미사를 달고 있다 —

    매운맛  ->  매운맛(작열)          L.ch.pungent_hot
    백탁    ->  백탁(유화 흰빛)        L.ap.milky_whiteness
    탁함    ->  탁함(구름감)          L.ap.cloudy
    기름짐  ->  기름짐(유동) / (도포)   L.tx.oiliness / L.tx.greasiness

**"어휘가 모자라다" 가 아니라 "맞춰 보는 방법이 거칠다" 였다.** 정규화 한 줄로
64% → 93% 다. 그러니 2절의 ④(없는 말을 새로 추가)는 생각보다 드물게 일어난다.

**정말 없는 것은 둘이다.**

    색상(hue)     L.ap 30개가 색 진하기·선명도·균일성만 갖고 **색 자체가 없다**.
                  "붉은 소스" 를 표현할 방법이 없다
    일반 기름 향   참기름 향·들기름 향은 있는데 상위 개념이 없다

**결과 ② 그런데 제형 판정은 3/5 에 그친다.** 어휘가 다 붙어도 그렇다.

    "저당 아이스크림, 얼음 씹히지 않게"   -> icecream    OK
    "토마토 살사"                        -> suspension  OK
    "쌀로 만든 부드럽고 덜 단 음료"        -> beverage    OK
    "고추장 베이스로 매운 소스"            -> beverage    빗나감 (기대 suspension)
    "마요네즈처럼 꾸덕한 드레싱"           -> beverage    빗나감 (기대 sauce_ow)

**왜 빗나가나 — 도달 가능성은 제형을 못 가른다.** 배타적 표지를 세어 보면
이유가 바로 나온다.

| 제형 | 그 제형에서만 닿는 축 |
|---|---|
| 현탁액 | 5개 — 섬유질감 · 웃물 · 꺼끌거림 · 건더기 크기 · 침전 |
| 아이스크림 | 4개 — 얼음 씹힘 · 녹는 성질 · 검성 · 단단함 |
| 음료 | **0개** |
| 소스 | **0개** |

네 제형 **전부**에서 닿는 축이 63개다. 걸쭉함·크리미함·백탁 같은 것으로는
아무것도 못 가른다 — 오히려 최근 내가 엣지를 넓힌 결과이기도 하다.

**음료와 소스를 가르는 축은 0개다.** 소스에만 닿는 둘(펴발림성·코팅성)은
사용자께서 "음료에는 안 채우는 게 맞다" 고 판정하신 것이라 남은 것이고,
음료에만 닿는 것은 하나도 없다.

**당연한 결과다.** 둘 다 `SC.emulsion.ow` 라 **구조가 같고**, 갈리는 것은
`APP`(용도)이다. 용도는 관능이 아니다. 사용자께서 "걸쭉한 음료도 만들 수
있어야지" 라고 하신 것이 바로 이 얘기다.

### 4.2.1 그래서 제형 판정은 두 조각이다

    SC (구조)   감각 서술어로 추론된다
                얼음 씹힘 -> 냉동 · 건더기 -> 현탁 · 유상+백탁 -> 에멀전

    APP (용도)  감각으로는 원리적으로 못 갈린다
                사용자가 말한 **명사**에서 와야 한다 — "소스" · "음료" · "드레싱"

제품 사전을 안 만들기로 했지만 이 자리는 비면 안 된다. **API 는 "이건 소스다"
를 상식으로 안다** — 사전이 아니라 API 가 `APP` 을 직접 말해 주면 된다.
그러니 `A2` 계약에 `SC` 와 `APP` 을 **따로** 받는 칸이 있어야 한다. 지금
알고리즘 그림의 `Define food-type` 은 하나로 뭉쳐 있다.

### 4.3 `A2` 가 초안을 낸다면 켜지는 기준이 바뀐다

사용자 피드백대로 `A2` 가 LEXICON·PARAMETER·EFFECT·STRUCTURE 초안을 낸다면,
"켜진다" 의 뜻이 하나 더 생긴다.

```
지금:      온톨로지에 있는 것 중에서 고른다
바뀌면:    온톨로지에 없으면 초안을 만들어 이 세션에서 쓴다
```

그러면 4.1 의 셋째 줄(무엇을 core 로 할까)에 답이 생긴다 — **`A2` 가 뽑은
정체성 축이 곧 그 세션의 core 다.** 제품 M 카드 파일이 하던 일을 A2 결과가
대신하고, 그것은 온톨로지가 아니라 제품 폴더에 산다.

**그러면 검증이 문제가 된다.** 지금은 `selfcheck_v2` 44건이 온톨로지를 지킨다.
A2 가 만든 초안은 그 검사를 안 거친다. 최소한 **초안이 기존 ID 를 가리키는지**
(새 `L.*` 를 지어내지 않았는지)는 봐야 한다.

## 5.5 이름 두 개가 아직 나쁘다

**`MEASUREMENT` 가 틀린 이름이다.** 사용자: *"measurement 라고 하니 뭔가
실험 데이터 같네. 내가 아는 M 카드는 제품의 성질을 기록하고 나타내는 카드."*
맞다. 이 카드가 담는 것은 실측값이 아니라 **한 축을 이 맥락에서 어떻게 읽고
어떻게 점수 매길지**의 정의다 — 앵커 문장 셋, 평가 주의, 합격선, tier.
실측값은 `data/*.xlsx` 와 `remi.db` 에 있고 카드에는 한 줄도 없다.

**`EFFECT` 도 헷갈린다.** 사용자: *"이름이 왜 EFFECT 인지."* 그 층은 재료
데이터베이스인데 이름은 그 안의 엣지를 가리킨다. 위 표에서는 임시로
`INGREDIENT` 로 적어 두었다.

둘 다 이번 개명(45파일 116건)에 이미 박혀 있으므로, 바꾸려면 한 번 더 돌려야
한다. 도구(`tools/rename_layers.py`)는 그대로 쓸 수 있다.
