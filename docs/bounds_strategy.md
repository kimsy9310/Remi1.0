# Bounds strategy — 제형별·재료별 상한/하한을 정하는 기준

2026-09-11. 사용자: *"효과 크기가 특정 양이 아니라 상한과 하한에 따른 기준값이네.
과거에 상한·하한을 정하는 작업을 부분적으로 했었는데 다시 확인할 필요가 있다.
제형별로 재료마다의 상한/하한을 정하는 전략과 기준을 생각해보자. 상한과 하한으로
SD 라는 단위를 정한 뒤, 통상 열과 비교해서 SD 값을 검증하는 전략은 어떤지?"*

**진단 문서다.** 실행 계획을 제안하되 아직 고치지 않았다.

---

## 1. 범위가 왜 이렇게 중요한가 — 사전의 단위다

온톨로지의 효과 크기 `weak / medium / strong = 0.3 / 0.6 / 1.0` 에는 **양이 없다.**
그 뜻은 "재료를 **1 SD** 움직였을 때 ±3 눈금에서 몇 칸" 이고,

    1 SD = (상한 − 하한) / RANGE_TO_SD          RANGE_TO_SD = 2.0 (09-11)

이라 **범위가 곧 사전의 단위**다. 쌀음료 실제 숫자:

| 재료 | 범위 | 1 SD | 크리미함 사전 | **1%p 당** |
|---|---|---|---|---|
| 정제 팜유 | 0 ~ 6.74% | 3.37%p | medium +0.6 | +0.178 |
| 해바라기유 | 0 ~ 9.07% | 4.54%p | strong +1.0 | +0.220 |

같은 `strong` 이라도 범위가 5~75% 면 1%p 당 0.03 칸이 된다. **범위를 두 배로
넓히면 사전이 절반으로 약해진다** — 온톨로지를 한 글자도 안 고치고.

범위가 하는 일은 셋이다:

    ① 사전의 단위      zsd = (hi − lo) / 2       v2adapter.build()
    ② 솔버의 경계      lo ≤ x ≤ hi              propose()
    ③ 실현 가능성      목표가 범위 안에서 닿나     C5 (아직 안 짬)

## 2. 지금 범위가 어디서 오나 — 세 곳, 세 질

| 출처 | 무엇 | 상태 |
|---|---|---|
| `data/palette.xlsx` 하한·상한 | 재료 × 제형, 손으로 채움 | 쌀음료 12/12 · 아이스크림 54/64. **다른 제형은 행 자체가 없다** |
| 기능군 `typical_use_pct` | 태그 24개에 "통상 사용량" | 팔레트에 행이 없을 때 폴백. **재료·제형을 안 가른다** |
| STRUCTURE `plausible_range` | 제형의 정의 파라미터 범위 | 유지·고형분에만 폴백으로 쓰임. 오늘 넷 채움, 전부 draft |

**팔레트의 `범위근거` 를 보면 질이 드러난다.** 쌀음료 12행 중 4행이 *"실측 18건
전부에 사용 — 사용 범위"* 다. README 도 적고 있다: *"실제로 쓴 범위이지 쓸 수
있는 범위가 아니다."* 실측 폭으로 범위를 잡으면 두 가지가 틀어진다 —

- 실측이 좁게 훑은 재료(구연산 0~0.5%)는 SD 가 작아져 **사전이 과대**해진다
- 알룰로스 20.1~25.8% 처럼 **0 을 안 품는** 범위가 나온다. "빼면 어떻게 되나"
  를 모형이 물을 수 없다

## 3. 범위를 정하는 기준 — 네 층위 중 어느 것인가

한 재료의 "범위" 라는 말에 넷이 섞여 있다. 갈라야 한다.

| 층위 | 뜻 | 예 (잔탄, 소스) | 누가 정하나 |
|---|---|---|---|
| **법적·안전 상한** | 이 이상은 못 넣는다 | 규정 상한 | 규격 |
| **기능 발현 구간** | 이 구간에서 물성이 움직인다 | 0.05~0.5% (그 위는 끈적) | 온톨로지 `limitations` |
| **감각 수용 구간** | 이 구간이 제품으로 성립한다 | 0.1~0.4% | 제품·용도 |
| **실측 폭** | 실제로 써 본 폭 | 0.2~0.3% | 데이터 |

**작업 범위(하한·상한)는 셋째 — 감각 수용 구간이어야 한다.** 그래야 ①(사전의
단위)과 ②(솔버 경계)가 같은 뜻을 갖는다: "이 제형에서 이 재료가 **의미 있게
작동하는 구간**". 법적 상한은 너무 넓고(사전이 무너진다), 실측 폭은 너무 좁다
(사전이 부푼다).

그리고 **하한은 대개 0 이어야 한다.** 필수 재료(필러·정체성 재료)만 예외다.
"빼면 어떻게 되나" 를 물을 수 없는 범위는 최적화에 반쪽이다.

## 4. 통상량으로 SD 를 검증한다 — 사용자 제안

**맞는 방향이고, 지금 데이터로 시험해 봤다.**

규칙 시안: 통상량 `typ` 이 `[lo, hi]` 안에 있고, `SD = (hi − lo)/2` 가 `typ` 의
0.25~2 배면 정상. 벗어나면 `범위근거` 가 있어야 한다.

결과: **62행 중 44건이 걸렸다.** 그런데 대부분 오탐이다 —

    알룰로스        범위 20.1~25.8   typical 12.5   -> "범위 밖"   감미료 태그의 통상량이 설탕 기준
    고감미도 감미료   범위 0~0.056     typical 12.5   -> "범위 밖"   같은 태그, 100배 다른 재료
    정제 팜유        범위 0~6.7       typical 10.0   -> "범위 밖"   유지 태그 통상량이 소스 기준

**원인은 검증 규칙이 아니라 통상량의 해상도다.** `typical_use_pct` 가 기능군
단위라 설탕과 스테비아가 같은 12.5% 를 받는다. **통상량이 재료 × 제형 단위여야
이 검증이 산다.** 그러면 두 방향으로 쓸 수 있다:

    검증    범위가 있는 행:  typ ∈ [lo, hi] 이고 SD/typ ∈ [0.25, 2] 인가
    생성    범위가 없는 행:  lo = 0 (필수 재료면 typ/3),  hi = typ × 3  을 draft 로

세 번째 쓸모: **A2 가 재료를 읽었을 때 "얼마나" 를 못 읽었으면 통상량이 첫 배합의
시작점**이 된다. 지금은 범위 중앙값(zbar)을 쓰는데, 0~9% 의 중앙 4.5% 가
해바라기유의 자연스러운 시작점은 아니다.

## 5. 실행 계획 (제안)

| | 무엇 | 왜 이 순서 |
|---|---|---|
| 1 | `data/palette.xlsx` 에 **`통상` 열** 추가 | 4절의 전제. 재료 × 제형 |
| 2 | 실측 있는 재료(쌀음료 12 · 아이스크림 54)부터 통상량 채움 | 실측 폭 안에 통상량이 있어야 하니 검증이 바로 된다 |
| 3 | `tools/check_bounds.py --check` — 4절 규칙으로 걸리는 행을 낸다 | 도구 규칙(CLAUDE.md). 팔레트 검토표에 붙인다 |
| 4 | 하한이 0 이 아닌 행을 전부 검토 — 필수 재료인가, 실측 폭인가 | 3절의 "하한은 0". 알룰로스 20.1 같은 것 |
| 5 | 범위 없는 행은 통상량에서 draft 생성 (`0 ~ typ×3`) | 다른 제형(소스·현탁·용도 넷)은 행 자체가 없다 |
| 6 | 기능군 `typical_use_pct` 는 마지막 폴백으로만 남긴다 | 재료·제형 통상량이 없을 때 |

**5 를 하고 나면** 소스·현탁액·드레싱·딥·컨디먼트·수프에 처음으로 재료 범위가
생기고, 그 제형들의 사전이 처음으로 단위를 갖는다. 지금은 `slot_bounds` 폴백이
STRUCTURE 파라미터와 태그 통상량으로 임시 스케일을 만들고 있다.

## 6. 정하지 않은 것

- **하한 0 규칙의 예외** — 필러 말고 어느 재료를 필수로 볼지. 정체성 재료(쌀음료의
  쌀)는 0 이 뜻이 없다
- **`× 3` 배수** — 통상량에서 상한을 만들 때 3 배가 맞는지. 감미료는 2 배도 넓고
  향료는 10 배도 좁을 수 있다. 기능군마다 다를 가능성
- **`0.25 ~ 2` 문턱** — 4절 검증 규칙의 폭. 첫 실행에서 걸리는 비율을 보고 조정
- **용량-반응 형태** — `dose_response_shape: saturating` 필드가 있는데 로더가 안
  읽는다. 범위 안에서 선형이라는 가정이 잔탄(0.3% 에서 급증)에는 틀리다. 별개 문제

## 7. 실행 결과 (2026-09-11 저녁)

5절 계획을 돌렸다. 도구: `tools/fill_typical_api.py` (API) → `tools/check_bounds.py --write --reset-old`.

| | 결과 |
|---|---|
| 통상 열 | 9제형 × 재료 = **958행** 전부 API 초안 (`통상출처 = api_draft`). 비용 약 $3 |
| 범위 | 958행 전부 다시 씀. **하한 0**, 상한 = API upper(오프노트 시작). 옛 범위는 `범위근거` 에 `이전 lo~hi` 로 남김 |
| 기능군 `typical_use_pct` | 223행이 API 와 자릿수가 다름 (고감미도 감미료 12.5 vs 0.02 등). 4절 진단이 맞았다. 폴백으로만 남는다 |

정한 것 (6절의 "정하지 않은 것" 답):

- **하한 0 예외**: API 확신 high 이고 k = 상한/통상 < 1.5 인 벌크 재료만 하한 = API lower_hint.
  걸린 건 아이스크림 넷 — 우유 10~70 · 설탕 5~18 · 탈지분유 2~13 · 팜 정제유 2~13.
  (`check_bounds.BULK_K`). 정체성 재료(쌀음료의 쌀조청)는 제품 행 문제라 아직.
- **k 문턱**: [1.5, 5] → **[1.5, 8]**. API 가 0.05→0.3 처럼 반올림해 k=6 이 흔했다(35건).
- **잔탄 limitations 0.5%**: 유지. 소스 잎에 걸린 limitation 이라 sauce_ow·dressing·dip(용량 부모가
  소스)의 API upper 0.6~0.8 을 0.5 로 잘랐다. condiment(현탁)는 스코프 밖이라 0.8 그대로.
- **용량-반응 형태**: API 가 재료×제형마다 줬다 (linear 584 · saturating 189 · threshold 72;
  잔탄·젤란·카라기난은 전부 threshold). `통상근거` 에 적혀 있고 로더는 아직 안 읽는다.

**부산물 — 음료 제형이 갈라졌다.** 원래 `APP.beverage` 정의가 주스·탄산의 클라우드 에멀전
(기름 ppm~수 %)이라 API 가 유지 0.15% 를 줬다. 쌀음료는 식물성 밀크(지방 1~3%)다.
`APP.beverage.cloud`(원래 정의) / `APP.beverage.milk`(신설, RV_rice_milk 가 여기 선다) 로 갈랐고,
`SC.emulsion.ow|APP.beverage` 는 둘의 가족 스코프로 남아 R-1 음료 관계를 같이 물려받는다.

남은 것:
- **RV_rice_milk 제품 행 12개** — 통상이 없고 옛 실측 폭 그대로. 실측이 쌀조청 55~64% · 알룰로스
  20~26% · 젖산 1.3~1.6% 라 마시는 음료가 아니라 **희석 전 베이스** 수치로 보인다. 확인 뒤
  제품 행을 (a) 지우고 제형 행을 물려받게 할지 (b) 덮는 행만 남길지 정한다.
- `tools/fill_typical_api.py --rebuild-review` 는 API 없이 팔레트에서 `data/typical_review.xlsx`
  를 다시 만든다 (사람의 판정·메모 열은 남긴다).
