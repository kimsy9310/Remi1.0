# Remi 법전 — 모든 세션이 읽는 규칙 한 벌

2026-09-17 (S1). **영문판 `RULES.en.md` 가 정본**이고 이 파일은 그 번역이다 (개정 5 기준). 둘이
다르면 영문판을 따른다. 사용자가 검토를 마쳐 E5(초안) · B4 하위 계층 · C8(보류) 을 빼고 전부
**확정**됐다.

읽는 법: 규칙에는 번호가 있고 번호는 바뀌지 않는다(뺀 규칙은 *폐기* 로 남긴다). 01~06장은 *왜*
를 설명하고 이 파일은 *무엇* 만 적는다. 이 파일만 읽은 세션이 온톨로지를 바르게 읽고 쓸 수 있어야
한다. 여기 없는 이름·레코드 꼴은 쓰지 않는다 — 먼저 여기에 더한다.

상태: **확정** = 사용자 결정 · **초안** = S1 제안, 검토 대기 · **보류** = 논의 미룸(*보류* 절에
어디서 정하는지 적음) · **폐기** = 뺐고 번호만 남김.

## 0. 수학 어휘

온톨로지는 그래프이고, 모형은 그것을 행렬로 읽는다. 이 법전의 모든 레코드는 아래 대상 중 하나이며,
각 낱말은 이 파일 어디서나 정확히 이 뜻으로만 쓴다.

| 낱말 | Remi 에서의 뜻 | 무엇에 해당하나 |
|---|---|---|
| **노드 (node)** | 이름 붙은 것; 그래프의 꼭짓점. id 를 가지며 자기 자신 말고는 아무것도 서술하지 않는다 | `L` `P` `SC` `APP` `ST` `ING` `FT` |
| **튜플 (tuple)** | 고정된 목록 여럿에서 하나씩, 정해진 순서로 고른 값 | 제형 `[SC, APP, ST]`; 빈 칸을 허용한 튜플인 스코프 |
| **성분 (component)** | 항목 하나 `{axis, direction, magnitude, …}`: 한 대상이 한 `L` 을 얼마나 움직이나 | 재료 엣지; `P.axes` 항목 하나; `DC` 항목 하나; `LESSON.observed` 항목 하나 |
| **벡터 (vector)** | 레코드 하나가 `L` 축들 위에 가진 성분의 목록 | `ING` 의 효과; `P` 의 `axes`; `DC` 하나; `LESSON.observed` 하나; `RP.compensate` 하나 |
| **스칼라 (scalar)** | 두 `L` 사이의 부호 있는 크기 하나 | `IN` 레코드 하나 |
| **행렬 (matrix)** | 벡터를 표로 쌓은 것 | 모든 재료 효과 = ING × L (모형의 Γ₀); 모든 `IN` = L × L; 모든 `P.axes` = P × L |
| **문장 (sentence)** | 사람과 API 를 위한 레코드. 구조화된 절반과 산문 절반 | `LESSON` `RP` |

수학 낱말은 아니지만 되풀이되는 것 둘: **스코프** = *어디서 성분이 참인가* 를 말하는, 빈 칸 있는
튜플(B5); **카드** = 한 제품의 한 축을 저장된 조각에서 합쳐 만든 보기(D1).

## A. 어휘

### A0. 이름공간 한눈에

| 접두 | 풀 이름 | 대상 | 레코드 하나가 무엇인가 | 예 | 소유 | 파일 |
|---|---|---|---|---|---|---|
| `L` | **Lexicon** | 노드 | 사람이 느끼는 것 하나의 낱말 — 맛 · 향 · 식감 · 외관 · 화학감각 | `L.tx.creaminess` | S1 | `layerL_lexicon.yaml` |
| `P` | **Parameter** | 노드 + 벡터 | 하나 이상의 `L` 을 대신하는 실험실 측정 지표 — 이름 · 단위 · 측정법 · `axes`(`L` 위의 벡터) | `P.apparent_viscosity` | S1 | `layerA_parameters.yaml` |
| `SC` | **Structure Class** | 노드 | 제품의 물리 구조 — 무엇이 무엇 속에 분산돼 있나 | `SC.emulsion.ow` | S1 | `structure_taxonomy.yaml` (신설) |
| `APP` | **Application** | 노드 | 용도 맥락 — 완성품을 어떻게 쓰고 내나 | `APP.beverage` | S1 | `structure_taxonomy.yaml` |
| `ST` | **State** | 노드 | 제품을 보관하고 먹는 온도 상태 | `ST.frozen` | S1 | `structure_taxonomy.yaml` |
| `ING` | **Ingredient** | 노드 + 벡터 | 재료 하나, 그 역할과 효과(`L` 위의 벡터) | `ING.xanthan_gum` | S2 | `layerC2_*.yaml` |
| `FT` | **Function Tag** | 노드 + 벡터 | 역할 — 같은 일을 하는 재료의 묶음 — 과 그들이 공유하는 효과 | `FT.thickener` | S2 | `layerC2_*.yaml` |
| `IN` | **Interaction** | 스칼라 | 한 `L` 이 다른 `L` 을 바꾼다 | `IN.0001` | S1 | `layerR_seed.yaml` |
| `DC` | **Decomposition** | 벡터 | 관용어를 `L` 위에 푼 것 ("깊은 맛" = [+umami, +kokumi, …]) | `DC.0001` | S1 (내용: S4) | `layerR_seed.yaml` |
| `KN` | **Kinetics** | — | `P` 나 `L` 이 시간에 따라 어떻게 변하나 (유통기한) | `KN.0001` | S1 | `layerR_seed.yaml` — 보류 |
| `LESSON` | **Lesson** | 문장 | 관찰: 어느 제형에서 어느 재료에 대해 무엇을 봤나 — 구조화 *및* 산문 | `LESSON.sugar_triple_role` | S1 | `layerS2_profiles.yaml` |
| `RP` | **Reformulation Pattern** | 문장 | 처방: X 를 줄이고 Y 를 지키며 Z 로 보상 — 근거로 `LESSON` 을 인용 | `RP.low_sugar_ice_cream` | S2 | `layerC2_ext_reformulation.yaml` |

재료 엣지(`ING`/`FT` 벡터의 성분)는 접두가 없고 `ING`/`FT` 레코드 안에 산다.

폐기 접두: `PO`(`P.axes` 로 접힘) · `SA`(`L` 의 v1 이름) · `IX`(`IN` 의 v1 이름).

### A1–A11. 규칙

| # | 규칙 | 상태 |
|---|---|---|
| A1 | 위 열 개가 유일한 이름공간이다. `PO` `SA` `IX` 는 폐기됐고 새 레코드에 나타나면 안 된다. | 확정 |
| A2 | id 는 `접두.소문자_snake`. 낱말은 `_`, 계층은 `.` 로 잇는다. `IN` `DC` `KN` `LESSON` `RP` 는 `접두.NNNN` 번호, 노드는 이름. id 에 한글 없음. | 확정 |
| A3 | `L` 은 사람이 느끼는 것 전부를 덮는다. 둘째 마디는 감각 종류: `ta` 맛 · `tx` 식감 · `ap` 외관 · `ar` 향 · `ch` 화학감각. 식감 낱말(걸쭉함 · 크리미함)은 `P` 가 아니라 `L` 이다. | 확정 |
| A4 | `P` 는 어떤 `L` 을 대신하는 실험실 측정 지표다. `P` 레코드는 이름 · 단위 · 측정법 · `axes`(`L` 위의 벡터)를 든다. 실측 `P` 가 없어도 시스템은 돌고, 있으면 확신도가 오른다. 제품을 `P` 만으로 서술하지 않는다. | 확정 |
| A5 | `FT` 는 역할이지 분류 트리가 아니다. 계층은 `specializes` 한 단뿐 (`FT.milk_protein specializes FT.protein`). | 확정 |
| A6 | `ING` 는 역할을 무게와 함께 적는다: `functions: [{function: FT.*, weight}]`. 무게는 세 낱말 중 하나(A9). | 확정 |
| A7 | 다른 노드를 가리키는 필드 이름은 가리키는 것의 이름: `axis` → `L`, `parameter` → `P`, `ingredient` → `ING`, `function` → `FT`. `from`/`to` 는 방향이 있는 `IN` 에서만. **그런 필드는 대상의 id 를 담고 표시명은 절대 담지 않는다** (`derived_from: sauce`, `derived_from: Oil-in-water emulsion sauce` ✗). | 확정 |
| A8 | **온톨로지는 영어로 쓴다.** 모든 노드는 `label`(짧은 영어 이름)을 갖고, 이름만으로 모호하면 `definition`(영어 한 문장)을 갖는다. 그 밖의 자연어 필드는 온톨로지 레코드에 두지 않는다 — `ko` 없음, 현지어 앵커·주의문 없음. 현지어 텍스트는 S4 의 것: locale 별 번역표(`lexicon_map_<locale>`), id 로 키를 잡고 영어 `label`/`definition` 에서 만든다. 사용자 문장은 어휘가 아니라 데이터다: 제품 카드(`intake` `unresolved`)에 원문 그대로 기록하고 S4 가 id 로 대응시킨다. | 확정 |
| A9 | 통제 어휘 — `direction {increase, decrease}` · `magnitude` 및 `weight {weak, medium, strong}` · `confidence {draft, low, medium, high}` · `functional_form {linear, threshold, saturating, non_monotonic}` · `tier {core, monitored}` · `goal {maintain, increase, decrease, minimize, maximize, target}` · `method benchmark_difference` · `scale_type diff_7` · `evidence_required {sample, sample_aged}` · `source {kind: literature\|expert\|prior\|measured\|user, date}`. | 확정 |
| A10 | `magnitude` 는 세 낱말 중 하나 **또는 숫자**. 낱말은 로더가 숫자로 바꾼다(weak 0.3 · medium 0.6 · strong 1.0). 숫자는 학습(E1)이 되돌려 쓰는 **재료 엣지에만** 나타난다. 역할 무게(A6)는 낱말로 둔다. | 확정 |
| A11 | **`L` 위 벡터의 모든 성분은 한 꼴이다**: `{axis, direction, magnitude, scope?, functional_form?, confidence, source}` — 재료 효과 · `P.axes` · `DC` · `LESSON.observed`. (`RP.compensate` 는 `L` 이 아니라 `ING` 위의 벡터라 C7 이 꼴을 정한다.) 비용 없음 — 선택 필드는 선택으로 남는다. 이득: 파서와 검사기 하나가 넷을 다 읽고, C6/C9 가 관찰과 엣지를 필드 단위로 대조할 수 있다. | 확정 |

## B. 제형과 제품

### B0. 용어

| 용어 | 뜻 |
|---|---|
| **structure** (`SC`) | 무엇이 무엇 속에 분산돼 있나. 물리가 정한다. |
| **application** (`APP`) | *용도 맥락*: 완성품을 어떻게 쓰고 내나 — 마신다(beverage), 끼얹거나 버무린다(sauce, dressing), 찍는다(dip), 소량을 곁들인다(condiment), 디저트로 먹는다(dessert). 사용자가 말한 명사에서 온다. |
| **state** (`ST`) | 보관하고 먹는 온도: `frozen` · `chilled` · `ambient` · `hot`. |
| **profile** | 튜플 `[SC, APP, ST]` 하나, **세 칸 모두 적는다**. 파라미터 범위 · 축 목록 · 필러를 가진다. 한국어: 제형. |
| **scope** | 같은 세 칸의 튜플인데 칸을 비울 수 있다; *성분이 어디서 참인가* 를 말한다(B5). |
| **product** | 사용자의 프로젝트: 제형 **더하기** 핵심 재료 · 정체성 축 · 원점(기준 제품). 한국어: 제품. `projects/<id>/` 에 산다. |
| **short key** | 제형의 파일 안전 별칭. 규칙으로 만든다(B8). |

### B1–B16. 규칙

| # | 규칙 | 상태 |
|---|---|---|
| B1 | 제형은 튜플 `[SC, APP, ST]` 하나다. 정본 이름은 그 튜플의 스코프 문자열, 예: `SC.emulsion.ow\|APP.beverage\|ST.ambient`. | 확정 |
| B2 | `APP` 은 재료 · 브랜드 · 제품을 담지 않는다. 새 `APP` 노드의 시험: *"제품을 어떻게 쓰나?"* 에 답해야 하고 *"무엇으로 만드나?"* 에 답하면 안 된다 (`APP.beverage.milk` ✗: 우유는 재료이지 쓰는 법이 아니다). | 확정 |
| B3 | `SC` 는 구조만 이름한다. 용도 · 상태를 점으로 잇지 않는다 (`SC.emulsion.ow.beverage` ✗ — 그것은 스코프이고 C1 대로 쓴다). | 확정 |
| B4 | `SC` `APP` `ST` 는 허용값 목록 셋이다. 지금은 어느 목록에도 하위 단계가 없다. `SC`: `emulsion.ow` `suspension`. `APP`: `beverage` `sauce` `dressing` `dip` `condiment` `dessert`. `ST`: `frozen` `chilled` `ambient` `hot`. `SC`/`APP` 에 값을 더하거나 값 밑에 값을 두는 것(드레싱은 소스의 일종인가?)은 건마다 정한다 → *보류 #1*. | 확정(목록) · 보류(새 값 · 하위 단계) |
| B5 | **맞춤.** 제형에는 **빈 칸이 없다** — `[SC, APP, ST]` 셋 다 적는다. 스코프는 일부 칸을 적고 나머지를 비운다. 스코프에 *적힌* 칸마다 제형의 그 칸과 같으면 스코프가 제형에 **맞는다**; 빈 칸은 어떤 값에도 맞는다; `any` 는 전부 비운 스코프다. (아래 예.) | 확정 |
| B5-1 | **특성으로 대신 맞추기.** 어떤 축에 *맞는 성분이 없을 때*(이름은 다르지만 물리는 같을 때 — 예: 딥이 소스처럼 행동), 로더는 **가장 가까운 제형**의 성분을 빌릴 수 있다: 같은 `SC` 를 가진 제형 중 정의 파라미터 범위(`discriminators`)가 가장 많이 겹치는 것. 빌린 성분은 확신도를 한 단 낮춰 쓰고, 스코프 대장(C9)이 모든 빌림을 적는다. 빌림은 정확한 맞춤을 절대 덮지 않는다. | 확정 |
| B6 | 제형이 받는 스코프 집합은 B5 로 **계산**하고 손으로 적지 않는다. 같은 성분이 맞는 스코프 여럿에 있으면 더 많은 칸을 적은 것이 이긴다. (알려진 노출: 너무 넓게 적은 스코프는 소리 없이 적용된다 — 02장.) | 확정 |
| B7 | 목록 셋과 점 표기 별칭표는 한 파일 `structure_taxonomy.yaml` 에 둔다. 제형 파일은 튜플만 든다. | 확정 |
| B8 | **짧은 키**, 만드는 법: (1) `APP` 의 마지막 마디; (2) `APP` 이 없으면 `SC` 의 마지막 마디; (3) `ST` 가 `ambient` 가 아니면 `_<ST>` 를 붙임; (4) 같은 `APP` 이 두 `SC` 밑에 있으면 `<SC 마지막 마디>_` 를 앞에 붙임. 키는 별칭이지 정본이 아니다. 모든 제형이 `ST` 를 적으므로 (3) 이 키를 짧게 지킨다: `ST.ambient` 는 기본값이라 붙이지 *않고*, `[SC.emulsion.ow, APP.beverage, ST.ambient]` → `beverage`, `[…, ST.frozen]` → `dessert_frozen`. 지금: `beverage` `sauce` `dressing` `dip` `suspension` `condiment` `dessert_frozen` (이관 때 개명 둘: `sauce_ow→sauce`, `icecream→dessert_frozen`). | 확정 |
| B9 | 제품은 **프로파일 넷**으로 정해진다: 구조(제형 튜플) · 재료(핵심 재료) · 감각(정체성 축 2~3 과 목표) · 원점(기준 제품). 구조 프로파일은 넷 중 하나일 뿐이다. | 확정 |
| B10 | 제품 하나에 카드 하나: `projects/<id>/product_card.yaml`. 제품은 제형을 짧은 키로 가리킨다 (`profile: beverage`). | 확정 |
| B11 | 정체성 축은 제형이 아니라 제품의 것: `identity: [{axis: L.*, …}]`, 둘 또는 셋. | 확정 |
| B12 | 사용자 고유 라벨(프로젝트명 · 고객 · 사내 코드)은 제품 카드의 `private:` 아래에만 둔다. 온톨로지 · 학습 · 프롬프트 · 다른 사용자 데이터에 절대 들어가지 않는다. | 확정 |
| B13 | 파생 제형은 부모를 짧은 키로 가리키고(`derived_from: sauce`) `confidence: draft` 로 태어난다. 검토 뒤 `status: reviewed <날짜>` 를 단다. | 확정 |
| B14 | **어느 `SC` 인가.** 분산상이 여럿이면(지방 방울 *과* 단백질 입자, 얼음 *과* 공기) 식감을 지배하는 상이 `SC` 다. 마시는 요구르트는 지방 방울이 있어도 `SC.emulsion.ow` 가 아니라 `SC.suspension`(카세인 응집체)이다. 시험: *그 상을 빼면 식감 부류가 바뀌나?* **제형당 `SC` 하나, 무게 없음**: 튜플은 선택자이고, 무게 있는 쌍은 Γ(t) 를 두 제형의 혼합으로 만들어 짧은 키를 깨고 스코프 불변식을 흐린다. 부차 상은 제형의 파라미터로 표현한다(예: 마시는 요구르트 제형에 작은 `P.oil_phase_fraction` 범위) — 그러면 `any` 스코프의 지방 관련 성분이 `P.axes` 를 통해 그대로 적용된다. `SC.dispersion` 같은 상위 값(에멀전과 현탁액 둘 다에 참)은 계층 → *보류 #1*. | 확정 |
| B15 | **저장 세 층.** *공유 온톨로지* — 사전값; 모든 프로젝트에 적용; **기밀**, 사용자에게 보이지 않음. *사용자 개인 층* — 이 사용자의 학습된 엣지 값 · `private` 라벨 · 카드 스냅샷; 이 사용자만 읽음. *제품 폴더* — 프로파일 넷 · 점수 · 배합; 이 사용자만. 같은 사용자의 이전 제품과 제형·핵심 재료가 같은 새 제품은 그 사용자의 학습값을 사전값으로 받는다(확신도 한 단 낮춤). 09-10 규칙(≥ 2 제품이 그 재료를 씀)이 성립하고 **사용자가 내보내기를 허락**하지 않는 한 개인 층에서 공유 온톨로지로 아무것도 옮겨가지 않는다. | 확정 |
| B16 | **변형 — 제약이 붙은 같은 제품.** "설탕 없는 같은 제품", "지방 30 % 줄인 것" 은 새 제품이 아니라 같은 제품의 새 **버전**이다. 원점 `o` = 현재 제품(거기서 모든 점수 0); 목표 `g` = 모든 core·정체성 축 *유지*(g = 0); 제약은 `x` 의 경계로 들어간다(C1 단계: `ING.sucrose` 제외, 또는 지방 역할 상한). 이것이 정확히 `RP`(X 줄이고 Y 지킴)가 쓰이는 자리다. 제약이 **핵심 재료**를 빼면(우유 음료의 무유 버전) 결과는 *형제* 제품이다: 옛 제품이 향미·구조의 참조이지 원점은 아니다 — 점수를 같은 자에 놓을 수 없다. | 확정 |

**B5 예.** 제형 `[SC.emulsion.ow, APP.dessert, ST.frozen]` (아이스크림):

| 스코프 | 맞나? | 왜 |
|---|---|---|
| `any` | 예 | 전부 빈 칸 |
| `SC.emulsion.ow` | 예 | SC 만 적혔고 제형의 SC 와 같다 |
| `SC.emulsion.ow\|APP.dessert` | 예 | SC 와 APP 이 적혔고 둘 다 같다; ST 는 빈 칸 |
| `SC.emulsion.ow\|APP.dessert\|ST.frozen` | 예 | 셋 다 적혔고 같다 |
| `SC.emulsion.ow\|APP.dessert\|ST.ambient` | **아니오** | ST 가 적혔고 다르다 — `ambient` 는 빈 칸이 아니라 값이다 |
| `SC.emulsion.ow\|APP.sauce` | **아니오** | APP 이 다르다 |
| `SC.suspension` | **아니오** | SC 가 다르다 |

따라서 `SC.emulsion.ow|APP.dessert` 로 스코프된 성분은 언 디저트 *와* 상온·냉장 에멀전 디저트
모두에서 참이라고 주장하는 것이다. 언 것에서만 참이면 저자가 `ST.frozen` 을 적는다.

**튜플 연습** (보류 #1 의 시험 사례):

| 제품 | SC | APP | ST | 비고 |
|---|---|---|---|---|
| 아이스크림 | `emulsion.ow` | `dessert` | `frozen` | 있음 |
| 슬러시 | `suspension` (시럽 속 얼음 결정) | `beverage` | `frozen` | 새 값 필요 없음 |
| 셔벗 | `suspension` | `dessert` | `frozen` | 새 값 필요 없음 |
| 마시는 요구르트 | `suspension` (B14) | `beverage` | `chilled` | 새 값 필요 없음 |
| 떠먹는 · 그릭 요구르트 | `gel` | `dessert` | `chilled` | `SC.gel` 필요 — 새 `SC` 의 첫 실제 사례 |

**제품 동일성 (B9, 세 관점).** 사용자는 배합을 바꿔도 같은 프로젝트를 같은 제품이라 부른다(버전).
전문가는 구조와 핵심 재료가 같으면 같은 *부류*라 부른다(두유 ≠ 우유; 두 회사 두유 = 같은 부류).
**모형**은 ±3 점수를 같은 자에 놓을 수 있을 때만 두 시료를 같은 제품이라 부른다: 같은 제형 · 같은
핵심 재료 · 같은 원점. 법전은 모형의 정의를 쓴다; 정체성 축이 바뀌면 새 *버전*(새 원점)이 시작된다.
제형만 같은 제품은 *형제*다. 한 사용자의 제품 사이 학습은 B15 가, 한 제품의 제약 변형은 B16 이
다스린다.

## C. 성분과 벡터

| # | 규칙 | 상태 |
|---|---|---|
| C1 | 스코프는 **성분에만** 붙는다 — 재료 엣지 · `P.axes` 항목 · `IN` 스칼라. 노드(`L P ING FT`)와 카드에는 스코프가 없다. 필드 이름 `scope`, 없으면 `any`, 표기는 하나: `SC[\|APP[\|ST]]`. | 확정 |
| C2 | 재료 엣지는 "이 재료(또는 역할)가 이 `L` 을 움직인다". `FT` 에 적힌 성분을 그 `ING` 들이 물려받고, `ING` 의 `overrides` 가 이긴다. 부정 효과(`direction: decrease`)도 여기 속한다. | 확정 |
| C3 | `P.axes` 는 측정 지표가 대신하는 `L` 의 벡터(옛 `PO`). 모든 `P` 가 가져야 하고, 비어 있으면 *채울 것* 으로 표시된다 → *보류 #3*. | 확정 |
| C4 | `IN` 은 두 목록: `interactions`(인과 스칼라, `from → to`, R-3 가 목표를 옮길 때 씀) · `overlaps`(`axes: [a, b]`, "둘 다 core 금지", B1 SCOPE 가 씀). 불확실한 관계는 적지 않는다. | 확정 |
| C5 | `DC` 는 관용어를 `L` 위의 벡터로 푼다; 성분마다 `direction` 이 있다. 내용은 locale 별 → S4. | 확정 |
| C6 | `LESSON` 은 관찰: `type` `scope` `about` `observed`(벡터, A11 성분) `when?` `statement`(산문) `source` `confidence`. 모든 `observed` 성분에는 대응하는 재료 엣지가 있어야 하고, 없으면 승격 대상으로 표시된다. | 확정 |
| C7 | `RP` 는 처방: `scope` `reduce` `keep` `compensate: [{ingredient, restores}]` `why` `evidence: [LESSON.*]`. Gap-fill(C4 단계)은 `RP` 없이 돌아야 하고, 있으면 `RP` 를 앞세운다. 숫자는 `RP` 에 살지 않는다. | 확정 |
| C8 | `KN` 은 지금 그대로 둔다. | 보류 → *보류 #4* |
| C9 | **스코프 대장.** 도구가 모든 성분을 한 표에 뽑고 불변식 다섯을 검사한다: (i) 스코프의 모든 마디가 그 목록의 값이다; (ii) 모든 성분이 제형 하나 이상에 맞는다; (iii) 같은 `(from, to)` 가 겹치는 스코프에서 부호가 다르면 좁은 쪽에 `why` 가 있어야 한다; (iv) 모든 제형의 모든 core 축에 재료 엣지가 하나 이상 닿는다; (v) `(owner, to, scope)` 는 유일하다. | 확정 |
