# 어떤 축이 제형에 걸리고 어떤 축이 안 걸리나 — 검증 전략

2026-09-07. 기본맛을 전 프로파일 기본 축으로 바꾸면서(커밋 `82473aa`) 드러난
문제를 일반화한다. **아직 구현하지 않았다.**

---

## 0. 왜 이 문서가 필요한가

아이스크림에 짠맛 카드가 없었다. 그런데 `ING.salt` 는 `scoped_to_structure_
class: any` 로 짠맛 엣지를 갖고 있었다 — **엔진은 아이스크림에서 소금이 짜다는
것을 알면서 물어보지 못했다.**

원인을 되짚으니 세 질문이 하나로 뭉개져 있었다.

| 질문 | 답할 곳 | 제형에 걸리나 |
|---|---|---|
| 이 감각이 **존재하나** | 렉시콘 + 물리적 전제 | 경우에 따라 |
| 여기서 **어떻게 재나** | M 카드 (앵커·평가주의·신뢰도) | **예** |
| 여기서 **최적화 대상인가** | tier (스펙 5.7) | **예** |

첫 줄의 답을 **카드 유무로** 하고 있었다. 카드는 누가 썼느냐의 기록이지 물리가
아니다. 기본맛은 고쳤지만 같은 함정이 나머지 210개 축에 그대로 남아 있다.

## 1. 지금 상태 — 실측

### 1.1 렉시콘의 대부분은 잠들어 있다

| 도메인 | 카드 있음 / 렉시콘 | |
|---|---|---|
| L.ta 맛 | 6 / 9 | |
| L.ar 향 | **6 / 118** | 향의 95% 가 선반 재고 |
| L.ch 화학감각 | 2 / 16 | |
| L.tx 식감 | 16 / 43 | |
| L.ap 외관 | 9 / 30 | |
| **합계** | **39 / 216** | **177개가 한 번도 활성화된 적 없다** |

선반 재고 자체는 결함이 아니다(스펙: "Shelf terms with no card are legal
inventory"). 문제는 **활성화 여부가 물리가 아니라 저작 이력으로 정해진다**는
것이다.

### 1.2 엣지 스코프로 판정해 봤다 — 절반만 맞는다

관능 축에 닿는 모든 경로(C 직접 엣지, 태그 엣지, R-1 합성)의
`scoped_to_structure_class` 를 모아 분류했다.

| 판정 | 개수 |
|---|---|
| 보편 후보 (경로가 전부 `any`) | 51 |
| 제형 의존 후보 (`any` 경로 없음) | 22 |
| 혼합 | 7 |

제형 의존 후보 22개를 눈으로 보면 **두 부류가 섞여 있다.**

**물리적으로 맞는 것 (14개쯤)**

| 축 | 스코프 | 왜 맞나 |
|---|---|---|
| 얼음 씹힘 · 녹는 성질 · 단단함 · 매끄러움 · 검성 | `SC.frozen.ice_cream` | **얼음이 있어야 한다** |
| 침전 · 웃물 · 꺼끌거림 · 섬유질감 · 건더기 크기 | `SC.suspension` | **분산 고상이 있어야 한다** |
| 기름 고리 · 분리됨 · 백탁 | `SC.emulsion.ow` | **유상과 계면이 있어야 한다** |

**저작 이력일 뿐인 것 (8개쯤)**

| 축 | 왜 의심스러운가 |
|---|---|
| 걸쭉함 · 흐름성 | 흐르는 것이면 무엇이든 있다. 스코프가 붙은 건 소스·현탁액에서만 엣지를 썼기 때문 |
| 기름짐 | 지방이 든 식품이면 어디든 느낀다 |
| 매운맛 여운 | 캡사이신 작열은 매트릭스와 무관하다. 지방이 여운을 늘리는 것은 **정도**의 문제지 존재 여부가 아니다 |
| 코팅 잔류 · 펴발림성 | 반고체면 어디든 |

**즉 엣지 스코프는 단독 판정 근거가 될 수 없다.** 카드 유무로 판정했을 때와
같은 함정 — 물리와 저작 이력을 섞어서 낸다.

## 2. 판정 기준 — 물리적 전제 하나로 간다

### 2.1 원리

> **어떤 축이 어떤 제형에서 존재하는가는, 그 제형이 그 축이 필요로 하는
> 상(phase)·상태를 갖는가로 정해진다.**

얼음 씹힘은 얼음이 있어야 한다. 기름 고리는 유상이 있어야 한다. 꺼끌거림은
분산 고상이 있어야 한다. 짠맛은 아무것도 필요 없다 — 먹을 수 있으면 짤 수 있다.

이건 **객관적이고 판정 가능하다.** 누가 엣지를 썼는지와 무관하다.

### 2.2 제형이 제공하는 것

Layer S 의 `structure_class` 를 상 목록으로 편다. 작은 표다.

| structure_class | 제공하는 상·상태 |
|---|---|
| `SC.solution` | 연속 수상 |
| `SC.emulsion.ow` | 연속 수상 · **분산 유상** · **계면** |
| `SC.suspension` | 연속 액상 · **분산 고상** |
| `SC.frozen.ice_cream` | 위 + **얼음** · **기포** · **부분합일 지방망** |
| `SC.gel` | 연속상 · **자립 그물** |

### 2.3 축이 요구하는 것

렉시콘 항목에 `requires` 를 붙인다. **대부분은 비어 있다.**

```yaml
- id: L.tx.icy
  requires: [ice]
- id: L.ap.oil_ring
  requires: [oil_phase, interface]
- id: L.tx.grittiness
  requires: [solid_particles]
- id: L.ta.salty
  # requires 없음 — 어디에나 있다
```

1.2 절의 분류로 보면 **`requires` 를 써야 할 항목은 15개 안팎**이고 나머지
200개는 빈칸이다. 하루치 작업이다.

### 2.4 그러면 활성 여부가 계산된다

```
축이 제형에서 존재한다  ⟺  requires ⊆ 제형이 제공하는 상
```

카드는 **어떻게 재는지**만 말하게 되고, **존재하는지**는 말하지 않는다.
지금 기본맛에 대해 `layerM_universal_axes.yaml` 이 하는 일을 전 축으로 일반화한
것이 이것이다.

## 3. 검증 절차 — 세 겹으로 겹쳐 본다

한 가지 신호만 믿지 않는다. 셋을 나란히 놓고 **어긋나는 곳**을 찾는 것이
감사의 산출물이다.

| 신호 | 무엇을 말하나 | 믿을 수 있나 |
|---|---|---|
| **A. 물리적 전제** (`requires`) | 이 축이 존재할 수 있나 | **정본.** 판정은 여기서 |
| **B. 엣지 스코프** | 누군가 여기서 움직일 수 있다고 적었나 | 부분적 — 저작 이력이 섞임 |
| **C. 카드 유무** | 누군가 여기서 재기로 했나 | 아니오 — 이력일 뿐 |

**어긋남의 종류와 뜻**

| 상태 | 뜻 | 조치 |
|---|---|---|
| A 가능 · B 없음 | 물리적으로 되는데 **아무 재료도 못 움직인다** | 온톨로지 결손. 엣지를 채운다 |
| A 가능 · B 있음 · C 없음 | 움직일 수 있는데 **물어보지 않는다** | ← **짠맛이 여기 있었다.** 보편 카드로 채운다 |
| A 불가 · C 있음 | 존재할 수 없는 축에 카드가 있다 | 카드가 틀렸거나 `requires` 가 틀렸다 |
| A 불가 · B 있음 | 존재할 수 없는데 엣지가 있다 | 스코프 오류 |

세 번째와 네 번째가 **지금 못 잡는 오류**다. 예컨대 현탁액에 크리미함 카드를
붙이면 아무도 막지 않는다 — 현탁액에는 유화 계면이 없는데도.

## 4. 도메인별 예상과 확인할 것

1.2 절의 실측을 기준으로 각 도메인이 어느 쪽인지 예상하고, **확인이 필요한
지점**을 적는다. 예상은 예상일 뿐이고 3 절 절차가 판정한다.

### L.ta 맛 (9개) — **보편**. 이미 처리함

수용체 수준이다. `requires` 없음. 2026-09-07 에 6개를 보편 축으로 열었다.
남은 3개(`L.ta.metallic`, `L.ta.oleogustus`, `L.ta.kokumi` 등)도 같은 취급이
맞는지 확인 필요 — oleogustus 는 지방산 맛이라 **지방이 있어야** 할 수 있다.

### L.ch 화학감각 (16개) — **보편**일 가능성이 높음

캡사이신·피페린 작열은 매트릭스와 무관하다. 지금 스코프가 붙어 있는 것은
현탁액에서만 엣지를 썼기 때문으로 보인다. 다만 **정도**는 지방상이 바꾼다
(여운이 길어진다) — 그건 R-2 상호작용이 다룰 일이지 존재 여부가 아니다.

확인할 것: `L.ch.cooling`(멘톨 냉감)이 온도와 얽히는지.

### L.ar 향 (118개) — **제품 의존**. 제형과 무관

향은 넣은 것에서 난다. 커피 향은 커피를 넣으면 나고, 그것이 음료든 아이스크림
이든 같다. **제형이 아니라 제품이 정한다** — 2026-09-02 에 현탁액에서 발효
핫소스를 떼어내며 확인한 그 구분이다.

그래서 향은 `requires` 가 아니라 **제품 사전**(착수 순서 2번)이 다룬다.
118개 중 6개만 카드가 있는 것은 결함이 아니라 정상이다 — 제품이 고르면 켜진다.

확인할 것: 매트릭스가 향 방출을 바꾸는 것(`P.flavor_release_dynamics`)은
존재 여부가 아니라 강도의 문제로 다뤄야 한다.

### L.tx 식감 (43개) — **갈린다.** 여기가 작업의 본체

| 갈래 | 예 | 근거 |
|---|---|---|
| 상태 의존 | 얼음 씹힘 · 녹는 성질 · 단단함 | 얼음이 있어야 |
| 분산상 의존 | 꺼끌거림 · 건더기 크기 · 섬유질감 | 고상이 있어야 |
| 유상 의존 | 기름짐 · 크리미함 | 지방이 있어야 |
| **보편** | 걸쭉함 · 흐름성 · 뒷맛 코팅 | 흐르는 것이면 |

`L.tx.creaminess` 를 어느 쪽에 둘지가 가장 미묘하다. 정의가
*"smoothness + viscous flow + fat lubrication + **dairy aroma**"* 라 지방을
요구하는 듯하지만, 무지방 제품도 검으로 크리미함을 흉내 낸다. **지방을
요구한다고 적으면 저지방 개발을 막는다.**

### L.ap 외관 (30개) — **갈린다**

| 갈래 | 예 |
|---|---|
| 유상 의존 | 기름 고리 · 백탁 · 분리됨 |
| 고상 의존 | 침전 · 웃물 |
| **보편** | 색 진하기 · 색 선명도 · 윤기 |

색은 어느 식품에나 있다. 지금 `L.ap.color_intensity` 가 음료 2곳에만 카드가
있는 것은 저작 이력이다.

## 5. 산출물과 순서

### 5.1 무엇을 만드나

1. **`phases` 표** — structure_class → 제공하는 상. Layer S 에 붙인다. 5줄
2. **`requires` 필드** — 렉시콘 15개 안팎에 추가. 나머지는 빈칸
3. **`tools/audit_axis_scope.py`** — 3 절의 세 신호를 나란히 놓고 어긋남을 낸다
4. **검토표** — 어긋남을 `draft_review.xlsx` 방식으로 판정받는다
5. **`selfcheck_v2` 검사** — "존재할 수 없는 축에 카드가 없다", "물리적으로
   가능한데 엣지가 없는 축 목록"

### 5.2 순서

| | 할 일 | 비고 |
|---|---|---|
| 1 | 감사 도구를 먼저 짠다 (`requires` 없이) | **지금 있는 것만으로 어긋남 목록이 나온다.** 어디를 손볼지 알아야 `requires` 를 쓸 수 있다 |
| 2 | 어긋남을 보고 `phases`·`requires` 초안 | 15개 안팎 |
| 3 | 검토표로 판정받기 | 특히 크리미함·기름짐·매운맛 여운 |
| 4 | 판정 반영 + selfcheck 검사 | |

**1번이 먼저인 이유.** `requires` 를 미리 다 써 놓고 감사하면, 내가 쓴 것을
내가 확인하는 꼴이 된다. 지금 데이터만으로 어긋남을 뽑아야 **어디가 실제로
문제인지** 가 나온다.

### 5.3 착수 순서 어디에 넣나

| 순서 | 할 일 | 상태 |
|---|---|---|
| 1 · 1.5 · 1.7 | 질문 정책 · 현탁액 분리 · 공정 기록 | 완료 |
| **1.8** | **축 의존성 감사 (이 문서 5.2 의 1~2번)** | 새로 |
| 2 | 제품 사전 | 향(L.ar) 처리가 여기 걸려 있다 |
| 3 | 재료 검색·잠정 등록·빈 곳 제안 | |
| 4 | 서술형 파싱 | API |
| 5 | Layer O | |

1.8 을 2번 앞에 두는 이유: 제품 사전이 향 축을 다루는데, **향이 제형 의존이
아니라는 판정이 먼저 서야** 사전이 무엇을 담을지 정해진다.

## 6. 열린 질문

**Q1. 크리미함에 지방을 요구할 것인가.** 요구하면 저지방 개발을 막고, 안 하면
현탁액에도 크리미함 카드를 붙일 수 있게 된다. 지금 판단으로는 **요구하지 않고**
"지방 없이 만들려면 검·전분으로" 를 `evaluation_note` 에 적는 쪽이 나아 보인다.

**Q2. `requires` 를 렉시콘에 둘 것인가 별도 파일에 둘 것인가.** 렉시콘은
"용어의 정의" 이고 `requires` 는 "물리적 전제" 라 성격이 다르다. 다만 항목마다
붙는 것이라 렉시콘이 자연스럽다. 불변식 3(append-only)에 걸리지 않는 추가다.

**Q3. 제형이 없는 제품은.** 사용자가 완전히 새로운 카테고리를 만들면 어느
structure_class 도 안 맞을 수 있다. 그때 `requires` 판정을 어떻게 할지.
